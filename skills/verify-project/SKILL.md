# 验证项目

1. 从当前项目说明、构建配置或 CI 中找到真实检查入口，记下文件依据。入口不清楚时先报告缺少什么，避免猜一个命令当作验证。
2. 根据改动行为选择最小相关检查；区分格式、类型、单元与业务验收。明确将执行的命令与目录，经现有 run_command 审批后执行。
3. 以退出码和实际输出判断结果；ok 只说明工具是否正常返回。失败时先记录证据，再按 diagnose-failure 的用途决定是否加载。
4. 只有相关检查通过才报告已验证。未运行、用户拒绝、超时或输出截断须单列，不将其计为通过。
5. 需要整理多个检查结果时，使用 load_skill 加载本包 report.md；单一检查直接报告命令、结果和局限。

完成条件：改动行为有相应检查证据，未验证部分已明确。所有文件修改与命令沿用程序审批；本说明不授予权限。
