# 定位执行失败

1. 取得失败命令、目录、退出码和相关日志；没有证据先收集，不把一次错误等同代码缺陷。
2. 依据日志区分参数、环境、依赖和业务代码问题。环境或依赖问题时按需加载本包 environment.md。
3. 给出一个可验证的假设及最小检查，使用现有工具取得证据。假设不成立就更新原因，不反复运行同一无效命令。
4. 需要修改时先读取当前文件版本，提出最小修改，通过原有审批后执行，再运行最初失败的检查。
5. 遵守当前请求、编辑和 token 限制。拒绝、中断或副作用未知时停止；不能通过另一工具绕过拒绝。

完成条件：原检查通过且有输出依据，或明确仍失败、已排除项及下一步。把推测、已验证结果和未执行动作分开。
