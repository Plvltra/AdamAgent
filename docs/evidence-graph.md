# 最小证据图（C08）

当前实现 C08.1：从现有授权文档索引提取关系候选。调用 `extract_graph(index.refresh())`，得到一次固定来源代次的不可变图；没有额外数据库、模型服务或知识发布。已增加 C08.2 有界两跳查询；C08.3 已接聊天工具，C08.4 真实五题对照已归档，见下文。

在 Markdown/TXT 语料中显式标注实体 ID 和名称，例如：

```text
[module:checkout|Checkout] calls [service:live|Atlas].
[service:live|Atlas] maintained_by [team:billing|Billing].
```

首版只识别 `calls` 和 `maintained_by`，不推测未标记普通 prose；这是有意收窄的最小后端。显式 `type:id` 表示身份，显示名不是连接依据。同名 Atlas 可以分别为 service:live、service:test；冲突的维护关系全部保留为候选，不自动裁决。

每条边保存原 Chunk ID、文件路径、原字节 SHA-256、片段行范围、片段内字符范围、逐字原文及 `explicit_marker_v1` 提取方法。片段可能跨行或由超长单行拆分，使用原片段行范围而不伪造更精细行号。没有显式完整标记则没有边；片段边界不自动拼接。边 ID 绑定来源版本和精确范围，重复传入同一来源不重复建边。

默认最多 1000 条边，可显式调整至 10000；超限整批报错，不交付貌似完整的半张图。权限、文件读取、总量及取消由原 DocumentIndex 完成；提取函数只接收已授权快照，不自行按证据路径打开文件。候选尚不等于经过人工确认的长期知识，发布仍归原 B12。

[业务验收](../tests/features/test_graph_evidence.py) 使用真实临时文件与 DocumentIndex：准确原文/版本、同名身份隔离、重复输入去重、冲突保留、不完整标记不造事实、边数失败保留原索引/文件、原授权拒绝。5 项场景通过；Ruff、Pyright、架构/文档同步和全量 pytest 按独立提交门禁执行。

模块关系见 [当前架构](architecture.md)。不调用付费模型，不修改真实用户会话，无截图或看图。

验证记录（2026-11-02）：全量 3352 项通过（四进程，534.45 秒），Ruff/格式/Pyright 通过；新增说明直接审查，既有 Python 注释无删除。

## C08.2 有界两跳查询

`query_paths(graph, "module:checkout", "team:billing")` 返回原边组成的有向路径；省略终点可读取跳数内各路径。默认两跳、100 个节点和 1000 次边遍历，跳数硬上限 4，节点/边超限报错而非伪装没有答案。路径内去循环，路径间保留不同原证据，不合成“模块由团队维护”等新边。未标记、无路径、反向及跳数外关系不虚构。

查询必须指定实体 ID，不能用同名显示名猜测身份。返回图代次、路径、节点和边计数，每条原边仍带完整证据。4 项业务分支覆盖真实两份文件的两跳证据、跳数不足/缺失/反向/同名拒绝、两种资源上限及循环。

业务验收见 [两跳查询](../tests/features/test_graph_query.py)。

C08.2 验证（2026-11-02）：相关 37 项、全量 3371 项通过（575.78 秒）；Ruff/格式/Pyright 通过，478 个文档链接有效，既有 Python 注释无删除。

## C08.3 当前源、文本融合与普通工具

GraphSearch 借用原 DocumentSearch，每次重读授权索引重新提取，不维护第二份缓存。文本查询与图刷新之间代次不同时明确失败；编辑、删除、读失败或撤销授权不回退旧图。文本与图候选按原 Chunk ID 合并，保留 text/graph 标记，不把相关性分数直接相加；原 B09 混合检索及其排序报告保留。

配置文档根目录后，通过 `search_graph_documents(query, source_id, target_id?, max_hops?)` 接入普通只读工具管线。聊天工具只允许 1～2 跳，完整原文证据装不下时明确失败，不返回半条路径。复用原发现/模式/Hook/预算/日志与主子路径策略，构造时不扫描、不下载。所有结果为待核实候选，不自动调用 B12 发布。

7 项 API/注册表场景核对文本/图来源合并、真实编辑及删除失效、代次竞争/坏源失败、plan 只读调用、参数与输出容量拒绝。3 项正式主子聊天 MockTransport 闭环通过；连同原文档工具相关共 16 项通过。按用户最新要求，小项只做相关验证，大项结束再跑全量。

## C08.4 固定五题真实对照

固定本地 Qwen3 4B / llama.cpp，同一问题和回答器分别读取原文本 top-1、图补充路径及原片段，每题每组一次请求，无工具选择与重试。语料为两个显式实体标记 Markdown 文件；包含单点、两跳、同名、无答案和真实修改后的资料。这个小样本只检验该语料与召回设置，不能外推普通自然语言抽取或一般可靠性。

| 组别 | 精确答案 | 答案与引用完整 | 输入/输出 token | 请求总耗时 |
| --- | --- | --- | --- | --- |
| 文本 top-1 | 1/5 | 1/5 | 1408 / 128 | 3044 ms |
| 图增强 | 5/5 | 4/5 | 4156 / 145 | 3326 ms |

两跳题是有益案例：图提供调用和维护者两个原来源，回答与引用完整。无答案题两组都正确返回 null，没有增益。资料更新题图增强回答 team:platform 正确，但只引用维护者来源，遗漏模块调用来源，因此不计完整通过。文本单点题输出 service:live|Atlas，实体意图相近但不符合精确 ID 格式，保留失败。

费用与币种未知，不把本地请求推算为免费账单。10 次真实请求保存固定题目、完整输入、回答、用量和耗时。初始 batch-01 在路径预检时失败，未请求模型；修正目录解析后另建 batch-02。原运行脚本和模型清单已记录哈希，缓存图模块没有运行时哈希，后补核对不能冒充请求时证据。

工程复现入口新增显式输出目录参数，不覆盖旧批次；只连接固定 127.0.0.1:8087 本地模型。模拟 HTTP 验收经过实际索引与源更新，验证固定十次请求、失败不重试、旧批次拒绝覆盖。评分分开核对精确答案、引用 ID 与必需来源覆盖；这仍不等于通用语义裁判。
