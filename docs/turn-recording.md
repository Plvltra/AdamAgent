# T9 单轮录制与离线重放

更新日期：2026-10-31

## 需求与交付阶段

目标是在不重复付费请求和外部动作的情况下重现一轮问题，比较当前控制流程与当时的模型/工具调用。完整任务见 [扩展需求](agent-maturity-tasks.md)。

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| T9.1 | 显式选定一轮，保存输入、响应、工具结果、必要配置和实际会话增量；有界格式校验 | 已实现，离线专项验收通过 |
| T9.2 | 独立录制/重放入口、替代模型与工具适配器、首次差异报告 | 待实现 |
| T9.3 | 成功、工具失败、流程变化、流式、缺失与中断记录的整体验收 | 待实现 |

T9.1 仅提供开发接口，正常聊天不会自动录制。当前尚不能从命令行离线重跑一轮，不把“文件能读取”当作“流程已重放”。

## 已实现的使用边界

调用方持有所选会话锁，在开始前调用 capture_seed，取得原历史、用户输入、工作目录、模型名称、运行模式及流程配置。配置显式选择 agent、context、tool_limits、memory、planning、reflection、review、subagents、artifacts；不序列化完整 AppConfig。

用 RecordingWriter 创建一个新文件，TurnRecorder 接收实际会话事件读取回调。RecordingModel 装饰原 ModelClient；build_application 的 decorate_tools 可将主执行器装饰为 RecordingTools。最后通过 TurnRecorder.run 包围一次原应用 send。可运行的组装示例见 [业务测试](../tests/features/test_turn_recording.py) 中的 recording_app。

这两个适配器仍调用真实模型客户端和工具执行器，保留原权限、批准、并发、预算、状态与异常。它们只在边界采集，不往 Conversation 添加工具名称或录制分支。主循环现在依赖 ToolRunner 接口；单轮编辑额度 ToolBudget 移至共享契约，原额度语义不变。

列表查询不属于所选执行轨迹。一个录制器只接受一轮，轮次结束后不能继续写观察记录。observe 可接收宿主明确提供的上下文、记忆、规则、委派、复核、额度及 Skill 资料；这些通道目前未自动接到各服务，T9.2 必须补齐动态资料重放所需的来源与状态映射。

## 文件与关联

格式为 UTF-8 JSONL，每行具有 seq、type、data。seq 从零严格递增；首条版本为 1，后续未知版本或类型拒绝。

| 事件 | 保存内容与检查 |
| --- | --- |
| recording_started | 开始前快照、历史事件及版本；不接受仍在进行的旧轮次 |
| call_started | 模型输入、工具 Schema、输出上限，或工具批次及来源、执行前编辑额度 |
| model_output | 流式文本和 response_end；必须属于当前模型调用 |
| call_finished | 完整模型消息与用量，或配对工具消息；受控错误描述；实际会话事件增量 |
| observation | 宿主提供的非可执行资料快照 |
| recording_finished | 调用终态、回答或错误、最后一段会话增量 |

call_id 使用调用开始的序号；模型/工具边界串行采集，工具批次内部仍可按原规则并发。工具批次必须来自前一个完整模型响应，成功结果的名称、参数、请求身份和输出要与实际工具日志一致。

原有 SessionLog 验证历史及增量；只允许这次用户输入对应的一个新轮次。声明成功时必须已有同内容的完整回答提交。complete 仅代表录制有明确结尾：一个 API 失败的轮次也可以录制完整，业务结果仍是失败。

## 资源与隐私边界

默认文件 32 MiB、单条 4 MiB、10000 个事件。可显式传 RecordingLimits；文件硬上限 256 MiB、事件最多100000，单条不能超过文件。每个 JSON 值限制深度32和节点数200000；拒绝重复字段、非有限数、无效 UTF-8、额外协议字段和非 JSON 对象。超限拒绝，不悄悄裁剪可重放数据。

连接配置中的 API 密钥、认证头、base_url、Hook 命令和 MCP 环境不进入起点。错误只保存类别、原因码、已知用量与 HTTP 状态，不复制原异常文本、属性或远端错误正文。测试验证真实 HTTP 请求仍使用密钥，但录制无该凭据。

业务消息、工具输出和已有日志保留原文。这不是对用户主动写入业务内容的任意秘密进行自动脱敏；分享文件前应审阅业务内容。

## 保存故障与不完整文件

- 仅排他新建，不覆盖已有录制或原会话。输入记录通过 flush/fsync 后才调用原动作。
- 动作结果保存失败立即停止，不重新请求模型或重复命令。可捕获的文件写入失败尽力回退到已确认前缀；回退失败时文件可能残缺。
- 原动作已抛异常时，录制失败用异常注记说明，不替换原始失败；终端显示异常也继续原样传播。
- read_recording 只读验证，不修复文件。仅最后一条没有换行的物理行可作为残缺尾部忽略，完整 JSON 缺少换行也保持不完整。
- 中间损坏、结尾后额外数据、关联不匹配或超限直接拒绝。没有明确结尾不能声明重放成功，未知用量继续未知。

## 验证与后续完成标准

T9.1 新增46项测试，加20项架构约束共66项通过。模型经真实 HTTP 客户端的 MockTransport；本地文件、命令、审批、会话投影和录制使用生产实现，不调用付费 API。

[业务验收](../tests/features/test_turn_recording.py) 覆盖计划→读文件→真实命令→计划完成→回答、工具错误、HTTP/连接/超时/流式中断、拒绝、显示异常、录制同步故障、重复动作防止和认证信息。 [格式验收](../tests/test_recordings.py) 覆盖坏字段/关联、资源上限、快照冻结、损坏与只读前缀。

T9.2 必须运行真实 Conversation、上下文与预算逻辑，替代外部结果而不是直接返回已存最终回答；重放不得启动真实模型、命令、编辑或子任务。需要独立诊断存储、动态资料快照及新旧身份关联，首次调用次序或参数差异要有位置。T9.3 再验证流程变更与实际中断，不用固定假模型宣称真实模型效果。
