# T9 单轮录制与离线重放

更新日期：2026-10-31

## 需求与交付阶段

目标是在不重复付费请求和外部动作的情况下重现一轮问题，比较当前控制流程与当时的模型/工具调用。完整任务见 [扩展需求](agent-maturity-tasks.md)。

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| T9.1 | 显式选定一轮，保存输入、响应、工具结果、必要配置和实际会话增量；有界格式校验 | 已实现，离线专项验收通过 |
| T9.2 | 独立录制/重放入口、替代模型与工具适配器、首次差异报告 | 已实现，11项业务验收及116项相关回归通过 |
| T9.3 | 成功、工具失败、流程变化、流式、缺失与中断记录的整体验收 | 已实现，25项新增场景通过 |

正常聊天不会自动录制。T9.2 提供独立开发入口，显式录制一次真实任务，再将该轮离线重放到全新诊断目录。T9.1 的低层接口仍可用；缺少完整运行资料的早期录制只能 inspect，不能作为完整重放输入。

## 已实现的使用边界

调用方持有所选会话锁，在开始前调用 capture_seed，取得原历史、用户输入、工作目录、模型名称、运行模式及流程配置。配置显式选择 agent、context、tool_limits、memory、planning、reflection、review、subagents、artifacts、no_progress；不序列化完整 AppConfig。B01.2 之前的录制可缺少 no_progress；重放只导入当时的工具反馈和停止原因，不使用当前默认阈值重做工具。

用 RecordingWriter 创建一个新文件，TurnRecorder 接收实际会话事件读取回调。RecordingModel 装饰原 ModelClient；build_application 的 decorate_tools 可将主执行器装饰为 RecordingTools。最后通过 TurnRecorder.run 包围一次原应用 send。可运行的组装示例见 [业务测试](../tests/features/test_turn_recording.py) 中的 recording_app。

这两个适配器仍调用真实模型客户端和工具执行器，保留原权限、批准、并发、预算、状态与异常。它们只在边界采集，不往 Conversation 添加工具名称或录制分支。主循环现在依赖 ToolRunner 接口；单轮编辑额度 ToolBudget 移至共享契约，原额度语义不变。

列表查询不属于所选执行轨迹。一个录制器只接受一轮，轮次结束后不能继续写观察记录。CaptureRuntime 通过 bootstrap.observe_conversation 接入实际入口、工具目录、记忆、规则、模式、委派、审查和共享额度观察；显式 Skill 正文及目录一并冻结。执行 ID 在原生成位置录制，重放从同一位置取回；正常聊天仍使用安全随机 ID。

SessionAccount 在 SharedTokenBudget 原有锁内观察决策状态，避免读取到并发子任务更新后的另一份账本。离线保留当时其他成员的消费和在途预留，主会话消费从新诊断日志计算，当前额度限制仍由生产预算代码判断。

## 文件与关联

格式为 UTF-8 JSONL，每行具有 seq、type、data。seq 从零严格递增；首条版本为 1，后续未知版本或类型拒绝。

| 事件 | 保存内容与检查 |
| --- | --- |
| recording_started | 开始前快照、历史事件及版本；不接受仍在进行的旧轮次 |
| call_started | 模型输入、工具 Schema、输出上限，或工具批次及来源、执行前编辑额度 |
| model_output | 流式文本和 response_end；必须属于当前模型调用 |
| call_finished | 完整模型消息与用量、可选缓存/输入前缀观测，或配对工具消息；受控错误描述；实际会话事件增量 |
| observation | 宿主提供的非可执行资料快照 |
| recording_finished | 调用终态、回答或错误、最后一段会话增量 |

call_id 使用调用开始的序号；模型/工具边界串行采集，工具批次内部仍可按原规则并发。工具批次必须来自前一个完整模型响应，成功结果的名称、参数、请求身份和输出要与实际工具日志一致。

原有 SessionLog 验证历史及增量；只允许这次用户输入对应的一个新轮次。声明成功时必须已有同内容的完整回答提交。complete 仅代表录制有明确结尾：一个 API 失败的轮次也可以录制完整，业务结果仍是失败。

B03.1 为模型结果和已知模型错误增加可选 `cache_usage` / `input_prefix`；旧 v1 无字段仍有效，新字段必须符合 [缓存观测契约](cache-observation.md)。重放复用已保存观察，不能重算随机客户端身份或冒充新的缓存命中；失败与未知总用量规则保持。

B03.2 在运行起点保存可选 context_layout；重放通过 Conversation 注入同一布局。旧录制缺省时保留原消息排列和预算，未知版本明确拒绝重放；新旧都运行生产选择、计划和工具配对逻辑，不用旧输出跳过控制流。

B04.2 在运行起点增加可选 runtime_state_version，context/state 观察保存来源快照及真实循环计数。重放运行原上下文构造并校验次数，使用当时冻结的状态资料；旧录制不新增观察，未知版本拒绝。源目录、模式、子任务 ID 与已知/未知用量属于业务证据，不复制全局配置或认证信息。见 [程序状态](runtime-state.md)。

B06.1 将实际语义选择或关键词降级来源冻结在原 memory 观察中；重放不加载 embedding。起点接受新的语义配置及旧版三个关键词配置字段，仍拒绝未知字段。详见 [语义记忆](semantic-memory.md)。

## 资源与隐私边界

B05.1 的起点增加可选 compaction_version；重放按该版本构造任务导向摘要，旧录制缺省时保持原摘要提示、输入和估算。当前问题、工具证据及原文位置来自被冻结的会话记录，不读取当前工作区来重造历史。见 [任务导向压缩](task-aware-compaction.md)。

默认文件 32 MiB、单条 4 MiB、10000 个事件。可显式传 RecordingLimits；文件硬上限 256 MiB、事件最多100000，单条不能超过文件。每个 JSON 值限制深度32和节点数200000；拒绝重复字段、非有限数、无效 UTF-8、额外协议字段和非 JSON 对象。超限拒绝，不悄悄裁剪可重放数据。

连接配置中的 API 密钥、认证头、base_url、Hook 命令和 MCP 环境不进入起点。错误只保存类别、原因码、已知用量、HTTP 状态及可选结构化缓存/输入前缀观测，不复制原异常文本、任意属性或远端错误正文。测试验证真实 HTTP 请求仍使用密钥，但录制无该凭据。

业务消息、工具输出和已有日志保留原文。B13.1/2 另行提供 [本地分享脱敏 API 与命令](recording-sharing.md)，只生成独立的待审副本，不改写原录制；有限规则无法识别任意秘密，分享前仍须审阅业务内容。

## 保存故障与不完整文件

- 仅排他新建，不覆盖已有录制或原会话。输入记录通过 flush/fsync 后才调用原动作。
- 动作结果保存失败立即停止，不重新请求模型或重复命令。可捕获的文件写入失败尽力回退到已确认前缀；回退失败时文件可能残缺。
- 原动作已抛异常时，录制失败用异常注记说明，不替换原始失败；终端显示异常也继续原样传播。
- read_recording 只读验证，不修复文件。仅最后一条没有换行的物理行可作为残缺尾部忽略，完整 JSON 缺少换行也保持不完整。
- 中间损坏、结尾后额外数据、关联不匹配或超限直接拒绝。没有明确结尾不能声明重放成功，未知用量继续未知。

## 独立命令行入口

以下示例在项目虚拟环境中运行。record 会执行真实任务，使用已配置模型并产生相应 API 消费；本轮工程测试使用模拟 HTTP，没有运行付费请求。

~~~powershell
python -m adam.recordings record --output .\capture.jsonl --text "解释 main.py 的入口" --workspace .
python -m adam.recordings inspect .\capture.jsonl
python -m adam.recordings replay .\capture.jsonl --output .\replay-run-1
~~~

record 可指定 --session、--model、--mode plan|act、--skill，以及原配置路径。已有会话必须可取得锁；原审批继续在终端执行。录制文件不能已存在。

replay 只需要录制文件，不加载当前模型配置、认证信息或外部工具服务。输出目录必须不存在；每次重放使用新的目录。目录包含独立会话 JSONL 和 report.json；报告带 kind=offline_replay，导入的工具日志代表录制时的事实，不代表本次又执行过这些动作。

| 报告状态 | 含义 | CLI 退出码 |
| --- | --- | --- |
| matched | 当前主流程消费完整录制，输入、事件及终态一致；原任务可能是成功，也可能是已录完整的失败 | 0 |
| different | 当前流程的第一个可观察调用、参数、内部事件或终态与录制不同 | 1 |
| incomplete | 缺少继续比较所需的数据，不能判定整轮一致 | 2 |

格式无效或输出目录不可用也返回2；人工中断返回130。difference 给出事件序号、字段路径、期望和实际值；actual_error 保留促使当前流程停止的业务原因。ReplayTape 固定首次停止原因：已知数据耗尽后，清理不能误报为流程差异；若缺失之前已经出现真实差异，也不会被后续缺失覆盖。流式片段单独保存在报告 output 中。

## 哪些代码会重新运行

真实运行：Conversation、RequestRunner、RequestPolicy、ContextBuilder、PlanningService、ReflectionService、CompactionService、ToolBudget、SharedTokenBudget，以及生产 SessionStore 的日志校验与写入。

替代边界：ReplayModel 返回原模型响应；ReplayTools 导入原工具拥有的事件及结果；外部记忆、项目规则、Skill、委派与审查状态使用当时快照。不会重新检查今天的文件内容，不启动工具执行器、子线程调度、命令、编辑、MCP 或网络客户端。

ReplayStore 在独立目录逐项比较内部生成事件；仅忽略新的时间戳、耗时和受控错误说明文字，输入、消息、身份、用量、状态和原因仍比较。工具实现内部、外部服务质量和操作系统 IO 故障不由本入口重新验收；对应边界有专门业务测试。这样既能发现主流程变更，又不会为了复现问题重复外部副作用。

## T9.3 整体验收记录

| 场景 | 已验证结果 |
| --- | --- |
| HTTP、连接未发送、超时、坏响应、未知用量 | 同一请求次数、重试、用量及失败状态；matched 同时保留原失败 |
| 流式取消，已知/未知用量 | 已展示片段、停止原因及有效历史一致，不提交残缺回答 |
| 分片工具参数与中文流式回答 | 实际工具来源和后续消息配对一致，片段和 response_end 顺序一致 |
| 第一次请求成功、工具失败、第二次请求失败 | 同一 turn 的两次请求、工具与原始输入关联保持 |
| 命令、文件编辑 | 录制阶段真实执行，重放不再次运行；原目标的后续外部修改保留 |
| 修改请求次数限制 | 当前真实主循环提前停止，报告最早差异和 request_limit |
| 六种有效前缀/残缺尾行 | 返回 incomplete，原会话及原录制不变；不重复命令 |
| 真正差异早于缺失 | 保留早已发现的请求参数差异，不降级成 incomplete |
| 回答保存 fsync 失败 | 原文件真实回滚且录制保存失败事实；离线不制造同一 OS 故障，明确报告轨迹不同 |
| 输入无效、只有头部、输出目录已存在 | 非零退出，不覆盖原目录或文件 |

[独立进程入口](../tests/features/support/recording_worker.py) 使用本地 TCP 模型服务和标准应用，真实发出请求或执行命令后在五处暂停，再由父进程强杀：

1. 请求正在等待响应；
2. 工具结果只写半行并 fsync；
3. 工具结果完整同步；
4. 业务轮次已提交、录制结尾尚未写入；
5. 录制结尾已经完整同步。

随后由另一个进程运行 replay。前四种明确不完整，第五种轨迹一致；服务端请求数不增加，命令标记仍只有一次，原 JSONL 字节保持不变。暂停与半行注入仅存在于测试入口，不向生产配置加入故障开关。

验收暴露并修复了缺失状态被 finally 清理观察覆盖的问题。ReplayStore 与外部结果游标现在共用首次停止原因，停止后不再消费录制或继续推断。既有差异定位与业务根因保留仍通过回归。
