# 知识候选、审查与发布

## B12.1 已实现的候选接口

[KnowledgeProposals](../adam/documents/knowledge_proposals.py) 从当前授权文档核对结构化候选，冻结原文证据并保存为 pending。调用者提出结论，程序验证来源；当前不会自动提炼语义、独立审查或发布，也不会把候选注入聊天和记忆。

构造时传宿主选择的根目录与 DocumentIndex。文件按工作目录、资料根目录及分块配置隔离，位于根目录下的范围摘要/candidates/短ID.json；模型不能指定候选 ID、状态或批准结果。当前独立 API 提供 create(proposal) 和 read(candidate_id)，模型工具及用户发布入口由 B12.2 接入。

| 输入字段 | 含义与边界 |
| --- | --- |
| statement | 待审结论，最多 2000 字符 |
| applicability | 适用对象、版本或条件，最多 1000 字符 |
| reasoning | 如何理解支持与反证，最多 2000 字符；不视为已证实 |
| valid_from / valid_until | 带时区的 ISO 日期时间；未知显式 null，结束须晚于开始 |
| support | 至少一条、最多八条实际原文引用 |
| counterevidence | 最多八条反证；没有已知反证时显式空数组 |
| source_generation | 提出候选时所依据的语料快照版本 |

引用复用 [来源审计](knowledge-catalog.md) 的 chunk ID、路径、文件版本、行号、块内字符区间和逐字 quote。同一原文范围不能同时登记为支持和反证；同一类内重复引用也拒绝。支持与反证都必须匹配本次重新读取的授权原文，不能只验证支持而忽略反证。

例如旧文档说“无限重试”，新文档说“从 2026 年 11 月开始最多两次”。候选可以提出“两次”，记录新文档为支持、旧文档为反证，适用范围限新版本，并写明采用新规则的理由。程序只确认这些引文确实存在，不判断新文档是否权威、是否取代旧文档，或模型提出的生效时间是否正确；这些留待独立审查和用户确认。

## 保存与失败边界

每份候选保存宿主生成的八位 ID、创建时间、范围、完整提案、内容摘要，以及 pending / unreviewed 状态。使用文件锁及原子快照，短 ID 碰撞有限重试且不覆盖旧记录；每个范围最多 256 份候选，单份读取上限 1 MiB。

创建先校验参数，再在锁内核对当前源和保存；来源变动、撤权、保存失败或取消均不发布任何内容。返回值和读取结果是副本，调用者修改字典不能修改已保存候选。原文、现有记忆和其他候选不被改写。

read 展示冻结证据，源文件后来修改或删除不会悄悄替换旧候选的内容，也不据此宣称证据仍当前。后续审查与发布须重新核对来源。候选损坏保留原文件并报错，恢复提示不会要求把它当作可丢弃的索引缓存。伪造 published 字段即使重算文件校验和也拒绝；候选本身没有批准状态入口。

本阶段复用原修改提案的边界原则：候选与批准分开、内容冻结、执行前重新核对来源。没有将知识事实塞入文件补丁或自动修改原资料；B12.2.1 已实现下方状态与确认接口；B12.2.2 已接入有界模型审查，B12.2.3 继续实现使用入口，B12.3 补组合故障验收。

## 验证

[18 项业务场景](../tests/features/test_knowledge_candidates.py) 使用真实冲突文件，验证支持/反证与时间、重启冻结、输入/返回值隔离、源变化、空反证、参数与自报批准拒绝、逐类证据核验、范围隔离、保存失败、撤权、取消、ID 碰撞和伪造发布状态。与原来源审计及架构检查合计 60 项通过，Ruff 与 Pyright 通过；提交门禁执行全量 pytest。没有调用付费模型，语义提炼效果尚未评估。


## B12.2.1 发布、撤回和当前知识

[KnowledgeLifecycle](../adam/documents/knowledge_lifecycle.py) 以同一范围的候选仓库为输入，另外保存 states.json。候选文件始终冻结，实际状态来自完整历史重放；每次决定保存修订号、候选内容摘要、审查 ID 与意见、决定来源、原因、时间和本次来源版本。状态历史最多 4096 条，使用同一把锁及原子快照；损坏或断链报错并保留原文件，不能当缓存清空。

| 操作 | 行为与边界 |
| --- | --- |
| inspect / history | 展示当时证据和决定，不宣称来源仍当前 |
| review | 宿主注入独立审查者；传入冻结候选，返回接受、修改或拒绝建议，以及支持/反证引用说明 |
| publish | 仅接受审查通过的候选；宿主界面展示候选和审查后取得明确用户确认；拒绝记为终止状态 |
| reject / withdraw | 用户拒绝未发布候选，或撤回已发布/待复核知识；重复同一决定幂等，不删除历史 |
| current | 只返回已发布、来源当前且在有效期的知识；开始时间含边界，结束时间不含边界 |

审查运行或用户确认期间不持文件锁。返回后重新检查候选内容与状态修订，发布前还核对当前授权原文。期间发生其他审查、拒绝或源变动，旧结果报错，不能覆盖新决定；不会自动重新问模型或复用旧批准。重复发布同一当前有效候选不新增事件或再次确认。

审查必须说明已提供的所有支持和反证 ID，禁止携带 approved 等发布字段；这只能校验结构与引用声明，不能证明模型理解了反证。审查者身份由宿主提供，独立模型适配见下方 B12.2.2。semantic_status 始终 not_verified，用户采用也不等于事实已证明。

状态为 pending → reviewed / changes_requested → published；拒绝进入 rejected，撤回进入 withdrawn。审查不接受时仍可重新审查，已拒绝或撤回候选不能复活。来源变化时，current 先保存 needs_review 并排除该知识；旧候选证据不改写，需要新候选重新审查和确认。版本覆盖整个配置语料，无关资料变化也会保守失效。检查反映一次读取的快照，不承诺文件此后不再变化。

权限撤销、源读取失败或状态保存失败直接停止，不能回退返回旧知识。即使原来源不可读，用户仍可撤回知识。有效期外知识不返回，但保留发布历史。本阶段没有自动向模型注入知识，也没有终端发布命令；这些入口按 B12.2.3 继续实现。

[27 项发布场景](../tests/features/test_knowledge_publication.py) 只模拟审查意见和确认回调，实际使用来源文件、文件锁、候选和状态落盘，覆盖锁外执行、过时结果、拒绝、重启、来源失效、时间边界、撤权、原子替换失败和损坏历史。相关候选与架构检查合计 66 项通过；Ruff、Pyright 通过，提交门禁运行全量 pytest。真实模型审查质量尚未验收。


## B12.2.2 独立模型审查

[KnowledgeModelReviewer](../adam/documents/knowledge_review.py) 实现宿主审查接口，只接收冻结候选，不继承提出者或主会话的消息。宿主明确传入 ModelClient、模型名、专用持久记录目录和单次 token 限额。当前没有自动聊天触发或命令入口，B12.2.3 接续实现；本次验证没有调用付费 API。

每个实例最多发送一次请求；无 tools，不执行模型返回的工具调用，不重试网络或格式错误。输入包含候选 ID/摘要、结论、理由、适用范围/时间、全部支持和反证；正文最多 64 KiB，超过时拒绝发送而不截断证据。输出默认上限 1024 token，可设 64～4096；本地接收意见上限 10000 字符。

单次预算默认 50000 token，可设 1～1000000；发送前用消息 UTF-8 字节数加输出限额作保守预留估算，服务端返回后记录可靠实际用量。估算不等于服务端收费承诺；实际超预算、未知用量均拒用意见。不将这种独立请求暗中记作已有聊天会话的免费操作；使用入口须显式发起并展示其独立消费。

请求以宿主分配的 16 位 review_id 保存，先写 started / intent，再调用模型；记录候选内容摘要、来源版本、完整有界请求、模型/提示词身份、输出限额、实际用量、耗时和受控原因。不保存连接密钥、HTTP 头或原始远端错误正文。返回正文最多保存 10000 字符，截断有明确标记，不能当有效意见。

记录中的 succeeded 只说明模型返回了格式有效且用量已知的审查意见。生命周期还会检查候选、来源与修订；模型请求成功后来源变化，意见不采用，状态仍待审，已发生的消费仍留证。即使意见建议 accept，也只能成为 reviewed，用户明确确认才会发布。

请求开始后若被强杀，intent 记录不能判断请求是否到达远端，消费保持未知；同 ID 记录无论成功、失败或 started 都不能覆盖或续发。连接未建立时记录 not_sent 和已知零消费；其他中断或传输故障没有可靠用量就保持未知。保存意图失败不请求，保存响应失败不交回意见；若连失败记录也写不下，保留原 intent，不伪造已结算状态。不存在自动恢复重发。

独立上下文有助于隔离提出者的聊天影响，但不保证模型独立判断正确；同一模型也可能重复错误。支持/反证 ID 覆盖只验证响应声明，不能证明它理解了证据，真实审查质量仍需人工对照。

[24 项业务场景](../tests/features/test_knowledge_review.py) 使用 MockTransport 和真实 LLMClient，覆盖 JSON/SSE、请求前留证、可靠/未知/超额消费、自报批准与工具调用拒绝、格式失败、取消、三类写入失败、来源变化、输入与预算上限以及重复请求。加发布场景与架构检查共 72 项通过；Ruff、Pyright 和文档链接通过，提交门禁运行全量 pytest。
