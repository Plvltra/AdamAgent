## 目标与分阶段交付

只读子 Agent 可以提出一个文件的一处替换。主 Agent 核对来源、展示差异并取得用户批准后，才通过原编辑流程应用。
候选存在不代表子任务成功、用户批准或文件已修改；子任务不能通过提案扩大权限。

- [x] T11.1：不可变提案、实际读取证据、当前版本及唯一替换验证、JSONL 保存与重启读取。
- [ ] T11.2：生产子任务注册 submit_proposal；主任务核对实际派发后收集、批准应用；复用编辑额度、规则、Hook、编辑日志及 T7 检查点。
- [ ] T11.3：两个真实子线程的冲突/非冲突、拒绝、外部改动、失败、重启及撤销验收。

当前不在生产模型工具目录注册 submit_proposal，也没有可用的主任务应用入口。
假 HTTP 场景使用测试专有的薄适配器验证 API 与真实执行器，不能代替后两阶段。

## T11.1 数据与来源

| 数据 | 由谁提供 | 保存内容 |
| --- | --- | --- |
| ProposalOwner | 可信宿主 | 主会话、主轮次、子会话与派发 run_id；主任务收集时还须核对实际委派索引 |
| ProposalEdit | 模型提出 | read_call_id、old_text、new_text、reason；不接受模型指定路径、版本、所属会话或批准状态 |
| ReadEvidence | 真实 read_file 记录 | 子轮次内读取请求/调用 ID、工具返回的实际绝对路径、完整文件 SHA-256、可见行范围 |
| EditProposal | 提交服务生成 | 随机提案 ID、所属派发、提交来源、读取证据、补丁及纯编辑规划得到的目标版本 |

read_file 的路径由现有 PathPolicy 解析，随工具结果固定保存。
后来更改输入路径或源文件不能改变这份历史证据；缺少路径和可见正文的旧结果或通用预览不能作为新提案依据。
模型可提出错误修改，程序验证来源与执行条件，不验证修改的语义正确性。

## 提交顺序与失败边界

1. 取得执行器固定的当前轮次、请求和提交调用；只查本子会话、本轮指定的已完成 read_file。
2. 核对真实输出成功、行号连续、路径与版本有效，旧文本全部位于实际返回的可见行。
3. 重新按当前读取权限打开记录中的目标，核对完整原字节版本；逐行比较，拒绝行内被截断的文本。正常的分段读取允许提交。
4. 复用纯 plan_edit 检查全文件唯一匹配、确有变更、文件大小与编码换行约束，计算目标字节的 SHA-256；不写文件。
5. 核对尚在执行的真实 submit_proposal 及其参数，预检后在会话锁下保存 proposal_submitted。只有落盘成功才返回候选。

输入/来源/过期错误作为 ToolError；日志 IO 故障作为 StorageError 停止。取消不追加候选。
当前文件在步骤 3 后仍可能被其他进程修改，因此未来的主任务应用必须再次授权并检查版本，不能信任曾经通过的检查。

每子轮最多 8 份提案；旧/新文本各最多 32 KiB UTF-8，理由最多 500 字符及 2000 字节，读取证据窗口最多 64 KiB。
提交参数中的 CRLF 规范为 LF；原文件 BOM、CRLF 等字节规则由原编辑规划保留。允许删除（新文本为空），不允许空旧文本、无变化及重复匹配。
证据窗口不补造末行换行；需要替换跨行文本时，应实际读到对应完整行。

## 持久化与恢复

proposal_submitted 追加到现有子会话 JSONL v4；回放重新核对所属子会话、轮次/请求/调用、真实读取及提交参数。
重复提案 ID、同调用重复提交、超额或同子轮改变派发身份均拒绝。
回放不重读当前源文件、不重算旧目标内容、不执行提案；未来应用时再核对当前版本和候选目标哈希。

提案保存后、工具结果或子轮成功提交前退出，候选仍作为已发生的诊断事实保留。
原恢复机制结束遗留轮次；不会自动批准、应用、重发或将候选视为可交付的成功子任务结果。
本阶段的显式 load_proposals 可读这些记录；主任务是否可收集和应用属于 T11.2 的委派验证责任。
