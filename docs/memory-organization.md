# B07 记忆整理

B07.1 已实现手动离线整理候选，B07.2 已支持确认保存概览、完整来源和有并发保护的撤销。B07.3 继续做组合故障验收；不会未经用户明确确认自动清理或合并记忆。

## 生成与查看

```text
/memory tidy
/memory tidy 整理ID
/memory tidy --global
/memory tidy 整理ID --global
```

省略 ID 时，对当前项目未删除记录生成新候选；提供 ID 时查看当时冻结的建议。全局整理须显式加 --global，不把项目与全局混为一个待修改范围。操作不创建聊天会话、不请求模型、不运行 embedding。

| 分类 | 离线规则 | 含义 |
| --- | --- | --- |
| 合并候选 | 同组正文逐字相同，且有效期相同 | 可由后续确认流程合并；仍须保留全部原始来源 |
| 保留 | 未发现同组记录，或尚未生效 | 不主动推断它应被删除 |
| 可能冲突 | 同一主体有不同表述/有效期，或无主体记录词语高度重合 | 仅提示人工核对，不判定谁正确 |
| 过期 | 已到 expires_at | 提示到期，当前阶段保留原条目和历史 |

有主体时只按明确的主体 ID 分组，同名不同 ID 始终分开。没有主体时，正文相同或关键词集合 Jaccard 重合度达到 0.6 才列入同组；英文按词、中文按相邻双字，沿用现有关键词提取。相似关系可传递成组，但不据此确认事实相同。一个主体也可能有很多互不矛盾的事实，因此“可能冲突”允许误报；词语不同的矛盾或同义重复可能漏报。这是可解释的离线初筛，不是语义真伪检测器。

正文的否定和有效期差异不会被当成安全合并。未来生效的记录单独保留；过期判断以候选的生成时刻为准。每个来源仅属于一个候选，最多处理 256 条；超限明确报错，不只整理前一部分却声称完整。

## 来源与保存边界

候选保存在记忆目录的 organizations/整理ID.json。每个候选绑定完整原文、ID、版本、主体、有效时间和来源；同样的确切来源与分类得到相同候选 ID。候选本身有独立短 ID 和创建时间，重复生成不会覆盖旧候选。

保存候选不修改 memories.json，也不向模型注入这些待确认建议。库后来更新时，查看旧候选仍展示旧版本，不悄悄替换为今日内容；确认阶段另外校验版本是否仍当前，B07.2 的入口见下文。

读取候选会按冻结来源和生成时间复算分类，拒绝错配 ID、来源重复、错误类型、篡改分类、残缺或越界路径。候选与当前范围不一致也拒绝，不跨项目展示。文件写入失败不打印成功，残缺文件无法被当成有效候选；原记忆和旧历史保持。

此校验用于发现损坏和内部不一致，不是文件签名或抵抗拥有文件写权限的攻击者；后续应用结果仍必须以真实记忆库的版本和原文核对。

## 确认与稳定概览

```text
/memory tidy accept 整理ID 候选ID
/memory tidy accept 整理ID 候选ID -- 用户核对后的概览正文
/memory list
/memory list --history 原记忆ID
/memory tidy undo 概览ID --revision 1
```

这些命令就是明确的用户决定，不交给模型解释。全局范围仍须附加 --global。接受按一个候选进行；保留和过期分类不产生新的概览。合并候选默认使用相同原文，也可提供整理正文；冲突候选必须提供正文，未提供时拒绝，不能让程序默选其中一条。

MemoryStore 持原有文件锁重读全部版本，比较候选的完整旧快照；任一源版本更新、删除或到期，整组拒绝。通过后一次原子替换保存所有旧记录的结束版本和一条独立的稳定概览。概览保存 organization/candidate ID、全部原 ID 与确切版本，并标记尚未验证。接受只表示同意保存，不证明事实成立；不是调用模型自动提炼经验。

旧原文和历史保留，当前召回只使用有效的新概览。概览有效期不延长来源：从确认时刻开始，到所有来源中最早的到期时刻结束。读取原来源仍可用历史命令追溯。重复确认相同候选不再追加版本；原结果后来修改或删除时返回该记录的当前状态，不恢复已删除结果。不能用同一已接受候选偷偷换一段不同的正文。

## 撤销与并发保护

撤销仅支持尚未修改或删除的初始概览，且每个源记录仍为本次整理产生的结束版本。概览或任一来源又被编辑、删除，整组拒绝，不覆盖后续操作。成功时一次原子替换追加概览删除版本和全部来源的恢复版本；恢复原有效期，不延长 TTL，不让原本已到期的事实重新生效。

接受与撤销都保留版本链，不回写或删除历史。保存失败时正式文件保持原字节，重新打开也不会出现一半结束或一半恢复。撤销后再次接受原候选不会把已删除概览复活；需要新的整理时重新生成候选。

## 工程验收

[16 项业务场景](../tests/features/test_memory_organization.py) 覆盖四种分类、完整来源、同名/项目/全局隔离、否定与冲突、CLI 不调用模型、重启、旧候选冻结、损坏及保存失败、数量和范围错误。连同已有管理、主体与架构回归共 70 项通过；提交门禁执行全量 pytest、Ruff 和 Pyright。

[B07.2 的 15 项业务场景](../tests/features/test_memory_consolidation.py) 验证概览/来源、幂等确认、明确处理冲突、接受与撤销保存失败、并发修改保护、TTL 与延迟撤销，以及真实请求与录制重放。B07.3 继续补真实进程并发与组合故障。
