# 有界视频输入

C06.1 提供显式宿主 API：`PyAVDecoder(VideoLimits(...))` 解码已经授权读取的完整字节，`VideoLoader(decoder, media.publish)` 用原 SessionMedia 发布视频和帧。安装可选依赖 `video`；固定 PyAV16.0.1，SDK仅在video/adapters内，不直接接模型或桌面动作。

首版支持MP4/MOV和Matroska/WebM的第一条视频流，不加载URL/外部协议、不提取音轨。默认输入32MiB、30秒、单帧2073600像素、最多解码3600帧、每秒采样一帧且最多32个样本、PNG总计32MiB。超过上限整批失败，采样超额提示增大间隔，不返回假装完整的前缀。元数据缺少时长时明确保留None；实际逐帧跨度和解码数仍受限。

帧保留原PTS、time_base分子/分母和 `PTS × time_base` 秒值，不用平均FPS推算，不为缺失时刻插值造帧。依据 [PyAV时间轴文档](https://pyav.org/docs/stable/api/time.html)。无时间戳、非递增时间、空流、损坏和超限分别诊断。保留编码像素方向，不自动应用显示旋转/像素宽高比；后续显示或分析需要单独处理这类元数据。

先完整有界遍历，再发布原视频和PNG帧；解码失败或取消不发布。发布阶段失败/取消可能留下已提交的部分证据，调用方不得自动重试或认为已回滚。每个媒体引用独立校验来源和版本，返回的VideoFrames将原片与帧关联；不另建视频数据库。原生单次解码只能在阶段边界取消，这些限制不是恶意媒体的进程内存沙箱。

2026-11-02 实际验收：8项局部场景通过，耗时2.17秒。真实Matroska/FFV1短片的4帧PTS为0/100/450/900，time_base=1/1000，时间0/0.1/0.45/0.9秒，容器时长0.901秒；间隔100/350/450ms证明可变帧率按实际媒体时间轴保留。独立视觉代理逐帧确认红/绿/蓝/黄，均完整64×48；主代理未读取图片。真实SessionMedia保存原片及4帧，另验证时长/分辨率/解码帧数/采样数/采样字节五类超限、损坏输入和解码中取消。

[时间轴及像素统计证据](evaluations/c061/vfr-frames.json)。原短片、帧图和复现脚本保留 `.cache/c061-video/`；pytest测试会生成临时短片，无需真实用户素材。此项只证明解码/引用，不证明时序理解或实时摄像头能力；C06.2/3仍待办。新增注释与发布失败边界已核对。

## C06.2 带证据的时序事件

`TemporalAnalyzer(analyze_frame)` 消费 C06.1 的 VideoFrames；回调只接收 FrameRef 和取消令牌，返回标签、原帧媒体引用、不确定性及分析来源。video包不导入视觉SDK或另造Agent循环，宿主可把既有 C04 图问接到此端口。模型图问仍走原请求/费用日志，时序整理本身没有新的模型调用。

结果为有序 VideoEvent：label、start_seconds、end_seconds、全部证据帧和分析来源。同标签只在原采样索引连续时合并；起止时间代表支持该事件的首尾**观测帧**，不能当作真实事件精确边界。coverage始终是sampled_frames_only，不承诺采样间隙没有其他事件。

先校验原样本的来源、PTS时间与递增性。调用方提供乱序、重复、外来或变化帧时，直接返回order_known=false及原因，不静默排序。缺帧仍可返回可见内容，但标记missing_samples和不确定性；帧分析报告unknown也降低顺序确定性。取消和分析失败不自动重问，已完成图问的用量和记录由原接口保留。

5项局部规则测试已通过：事件区间与全部证据、乱序不调用后端、缺帧降级、不确定/错误证据、取消后不调用剩余帧。此部分测试的帧语义端口是明确替身，真实视觉验证另列，不用规则测试冒充视觉理解。
