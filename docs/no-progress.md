# B01 无进展检测

本章是 [完整练习路线](agent-book-practice-plan.md) 的第一个增量。原书位置见 [B01 索引](agent-book-feature-index.md)。

## B01.1：独立策略 API

`NoProgressGuard` 观察工具的实际结果，用名称、规范化 JSON 参数、失败类别和宿主核实的外部版本生成摘要指纹。不同调用 ID、对象字段顺序、JSON 空白或 Unicode 转义不会构成新进展。每轮、每个主/子执行器各有独立实例，只保留最近一个指纹，内存不随调用历史增长。

默认同一失败第一次继续、第二次提醒、第三次停止。`NoProgressConfig` 支持开关和阈值，满足 `2 <= warn_after < stop_after <= 64`；B01.1 提供程序化配置，B01.2 已接入 TOML 和生产聊天。策略返回不可变结论，由集成层负责模型提示、日志与实际停止；它不会自行执行或重试工具。

观察发生在动作之后：前两次文件不存在，第三次已由用户修复，则真实读取成功会清空连续失败。工具名、参数、失败类别或可信版本变化也开始新计数；模型随意声明“我修好了”不能作为可信版本。停止结论在本实例内锁定，新用户轮次重新开始。

命令 `ok=true` 只代表正常启动/结束，非零 `exit_code` 仍是失败，按退出码分类。没有统一机器码的普通工具错误暂以规范化受控错误说明区分类别；原错误仍由调用方保存。命令 stdout/stderr 的变化不直接算进展，避免时间戳绕过检测。宿主如有可靠文件/环境版本，单独传 `evidence_version`；策略不会主动扫描工作区或猜测外部变化。

成功读取、翻页、正常 pending/running 状态不计失败。策略拒绝、规则补充、人工拒绝、子任务要求主任务批准以及取消交回原有流程处理，不能因此触发“修复工具错误”。这些非失败观察会结束当前失败序列。

边界：这是“连续同一种失败”检测，不是通用任务完成判定；交替调用、不断换参和反复成功但无意义的读取仍由已有总额度控制。它不取代请求/工具/token/编辑上限、权限或反思。无法识别尚未由工具/宿主报告的环境变化。

## B01.2：实际聊天、日志和回放

默认启用以下配置；省略整段也使用这些值。关闭只停用连续失败检测，不解除原请求、工具、编辑或 token 上限。

```toml
[no_progress]
enabled = true
warn_after = 2
stop_after = 3
```

bootstrap 分别给主任务和子任务的 ToolExecutor 注入配置。执行器按 `(session_id, turn_id)` 重建检测器，同轮的多次模型请求共用计数，反思请求不会把计数清零。新轮次重新开始；子任务继承阈值但不共享检测实例。已有额度、权限、批准、Hook 和取消仍在原边界处理。

每次工具结果先观察、再编码；tool_finished.output 与实际发送给模型的结果包含同一份 `no_progress`：`action`、`repeats`、`fingerprint`，提醒/停止时增加受控 `hint`。它是宿主保留字段，工具原结果中的同名字段被移除。换工具 ID 不能清零。提醒属于下一次模型请求的工具上下文，不新增聊天命令，不反复打印额度。

达到阈值时，先保存此次工具结果，再抛出公共 NoProgressError，原轮次收尾写入 `status=failed, reason=no_progress` 和耗时。已完成的模型请求仍为 succeeded、用量正常结算；这一轮输入和工具链不加入有效聊天历史。CLI 继续展示公共错误，不增加底层异常分支，Conversation.send 不增加检测逻辑。

单批多次相同调用也累计，按模型调用顺序判定；触发停止后不再派发后续动作，已有只读线程按原调度器取消/清理。停止观察可能发生在同一批内，程序不会为重复批次额外申请一次模型请求。B01.3 已验收并发和恢复边界，详见下节。

输出观察也占 max_result_chars：必要时缩短原结果预览，保留实际状态、退出码和附件引用。附件保留原工具正文，新增观察保存在工具结束事件中，不改写附件。保存失败、Hook 故障和取消沿用原错误，不伪装成 no_progress；未知消费仍阻止后续请求。

新录制冻结 no_progress 配置。早期录制可缺少这一配置；离线重放导入已记录的工具结果和失败原因，不用今天的策略重新执行工具，也不补造旧策略值。真实模型是否更善于换策略尚未评估，本轮没有调用付费 API。

## B01.3：版本证据、并发与重启

文件解码失败与编辑冲突可能在外部修改后仍返回同一句错误。现在 text_file / edit_tools 把**本次已授权、完整、有界读取**取得的原字节版本通过 FileStateError / FileResult 传到执行器。原地不变的失败继续累计；版本变了则从 1 开始，仍保留实际失败。没有增加第二次读文件、目录扫描或模型请求。

版本是本地对象元数据，不从工具 JSON 的 version/evidence_version、模型参数或文字承诺提取。工具输出伪造 no_progress 仍被替换为宿主观察。权限/参数预检、超大文件和操作系统读取失败未取得完整字节时不猜版本；这些错误及非文件工具仍使用原失败指纹。任意工作区变化不会自动清零命令失败。

并发批内按原调用顺序观察，达到停止阈值后清理正在运行的读取，不派发后续命令/编辑。已开始但未交付的结果不会补造成功：原 JSONL 留下没有 tool_finished 的开始事件，诊断视图暂保留 in_progress，表示记录未收尾，不能据此认定后台还在运行。下次持锁打开时，既有恢复机制将其标为 interrupted；已记录的 no_progress 轮次原因不被覆盖。清理超时仍由 ToolCleanupError 报告残留线程，不能声称已停止全部动作。

在提醒或停止结果落盘后、轮次结束前真实强杀进程，重启只追加 interruption；不能从工具反馈推断整轮已完成。已经结算的用量保持已知，旧失败输入不进入有效上下文，不自动重发模型或工具。只有显式新输入才创建新轮次，从第 1 次失败重新计数。两个并发子任务独立累计，主任务仍可正常收集失败并回答。
