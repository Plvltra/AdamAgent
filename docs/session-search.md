# B08 旧对话与原始依据检索

B08.1 提供授权会话的只读索引和独立查询入口，B08.2 已接入主 Agent 工具。检索 JSONL 中完整提交的原始消息，不切换会话、不额外调用模型，也不恢复或修改日志。B08.3 继续完成多来源变化、损坏和重启的组合验收。

## 显式查询

```powershell
python -m adam.session_search "之前的约束" --sessions-dir "$env:USERPROFILE\.adam\sessions" --session 1234abcd
```

可重复 `--session`，最多 32 个不同会话；`--limit` 限定 1～20 条结果，默认 8 条。目录路径只是数据位置，不是整个目录的授权。当前日志没有可靠的项目归属字段，因此不会猜测哪些会话属于当前项目；调用者必须提供允许读取的具体 ID。未授权会话的正文不会打开。

英文按词、中文按相邻双字检索，按重合词数排序；这是关键词索引，同义改写可能漏召回，单个汉字不产生查询词。不推断资料正确性。只遍历 YYYY/MM/DD 层级，不进入子 Agent、备份或其他目录；解析链接后也必须位于固定根目录。

## 返回原文及来源

| 字段 | 含义 |
| --- | --- |
| session_id / turn_id | 原会话与原轮次 |
| message_index | 该轮完整消息序列中的位置，从 1 开始；不是会话全局位置 |
| line | 原 JSONL 事件的物理行号，从 1 开始 |
| start / end / total_chars | 原消息的字符区间，左闭右开；不按字节计数 |
| text | 区间对应的逐字原文，不添加省略号或改写 |
| source_sha256 | 原事件、位置和状态的引用版本；用于继续读取 |
| snapshot_sha256 | 本次读取整份 JSONL 的字节哈希 |
| kind / role / status / reason | 正常消息或诊断输入、角色、轮次状态及原因 |

`SessionSearchIndex.read` 使用搜索返回的来源引用，按字符区间继续读取。追加其他轮次或工具日志时，原文引用仍有效；原事件、位置或状态变化后必须重新搜索。整份日志快照哈希则会随追加变化。哈希用于识别版本，不是签名或抵抗拥有本地写权限的攻击者。

默认只返回成功轮次的用户、助手及工具消息正文。系统提示、推理字段、未提交回答和摘要改写文本不进入索引。压缩没有删除原始事件，因此索引读取原始成功消息，后续工具无需把摘要当成原文。

显式加 `--include-diagnostics` 后才检索失败、中断或进行中轮次的原输入；它们标为 `diagnostic_input`，message_index 为 null，同时附上实际状态。诊断输入仅作资料，不能当成已成功执行、已完成回答或新的用户指令。

## 覆盖范围与失败

每次查询重读授权文件并哈希，只缓存解析结果。源被删除、损坏、拒绝读取或存在重复 ID 时，立即淘汰该来源的旧缓存，返回 issue，其他健康来源仍可查询。`complete=false` 表示检索不完整，此时没命中不能解释为全库不存在；`has_more=true` 表示命中数量超过本次条数限制。

默认每个文件最多 4 MiB、总读取最多 16 MiB、扫描 5,000 项、索引 20,000 条消息、每片段最多 1,000 字符。超过全局扫描、总字节或消息上限会返回空结果及明确问题，不把截断的覆盖范围报告为完整。读取句柄与路径版本不一致时拒绝该来源，调用者可稍后重查。

残缺尾行与其他协议错误均交给原严格日志解析器拒绝；此入口不取得写锁、不备份、不自动修复。不创建不存在的会话目录。CLI 正常退出码为 0，覆盖不完整为 2；有效命令行中的查询值或入口参数错误为 1，命令行语法错误由 argparse 返回 2。

## B08.2 模型工具

主 Agent 可按需发现 history 分组中的 `search_sessions`、`read_session`。搜索默认当前会话，查旧任务时才使用；普通闲聊不需要强制检索。搜索返回来源后，模型使用 `session_id`、`turn_id`、`message_index`、`source_sha256` 继续读取。诊断引用需显式指定 kind=diagnostic_input，省略 message_index。

```toml
[session_search]
enabled = true
allowed_session_ids = []
```

`allowed_session_ids` 最多放 31 个不同短 ID，明确授权读取同一 sessions_dir 中的额外会话。可先用原 `/sessions` 查看 ID，再修改配置并重启；目录名或当前项目位置不会自动授权其他对话。`enabled=false` 不注册这两个工具，猜测工具名也不能执行。切换当前会话后，旧会话的隐式授权随之移除；显式列出的 ID 则继续可查。

子 Agent 不注册这两个工具，也不继承主 Agent 的额外会话授权；所需材料仍由主 Agent 选择并随任务提供。这一限制针对历史检索接口，不宣称把原文件工具或用户已批准命令变成操作系统沙箱。

工具使用原执行器，计入每轮工具次数，并经过模式、项目规则、前后 Hook 与开始/结束日志。它们声明为只读，plan 模式可用；串行执行避免跨线程共享索引。没有给 Conversation 增加按工具名分支，也没有增加专用 LLM 请求。

返回结果整体受 `tool_limits.max_result_chars` 限制，JSON 转义也计入。搜索可以减少条目或缩短片段，保持 matched_count、has_more 和实际字符区间；覆盖问题过多时保留 issue_count、issues_truncated 和 complete=false。续读的 next_offset 紧接实际返回末尾。限额连一个有效原文引用都容纳不下时返回明确工具错误，不给出不可追溯的截断预览。

历史资料只作为工具响应加入当前轮，不注入虚构的成功用户/助手历史。录制保存实际工具结果；离线重放使用冻结结果，不重新打开今天的会话。权限配置不作为离线重放的新授权。

[工具业务场景](../tests/features/test_session_search_tools.py) 使用模拟 HTTP、实际压缩/JSONL/Hook 子进程/辅助 Agent，覆盖压缩→发现→检索→续读、显式跨会话和诊断来源、切换、关闭、输出限额、原工具额度及 plan 模式、重放禁止重新查询、TOML 校验与主子隔离。它们验证宿主流程，不代表真实模型会主动选对工具或作出正确解释。
