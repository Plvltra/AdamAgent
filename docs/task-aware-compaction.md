# B05 面向当前任务的压缩

B05.1 已实现工程接入，B05.2 已提供固定保真样本和引用审计。沿用 V3 的 CompactionService、连续历史覆盖和独立摘要事件，没有另一套压缩框架。B05.3 的模型查询对照尚未完成，真实模型是否更准确仍待评估。

## 输入与来源

自动摘要的 current_task 包含本次 turn_id、用户原文和已执行的完整工具链。模型在摘要时能知道当前在查什么、刚获得什么结果；这些内容仅帮助选择相关旧资料，不计入 source_turn_ids，不因为摘要成功就把未完成任务写入有效聊天历史。

旧素材仍为最早未覆盖的连续成功轮次，保留 turn_id 和协议消息顺序。source_positions 给出每轮消息数量，索引从 0 开始；提示要求关键结论使用 `[turn_id:message_index]`，工具结论保留 tool_call_id。已有摘要的 ID、累计覆盖轮次及原引用随输入提供；原始 JSONL 永不被摘要替换。

运行时的引用要求属于模型输出约定，不以引用检查阻止聊天摘要提交。B05.2 提供独立、只读的原文引用审计；引用可定位仍不等于结论正确，语义需显式判读。样本和入口见 [压缩保真评估](compaction-evaluation.md)。

手动 `/compact` 没有新的用户问题，current_task 明确为空，继续生成通用交接摘要。自动路径的当前前缀在规划时复制；后续工具循环追加消息不会改变已经规划的来源。

## 预算、记录和失败

当前任务、旧摘要、来源信息及素材一起估算摘要输入。当前工具链不截断；连最早一轮旧素材也放不下就停止，不浪费摘要请求。其余请求次数、共享 token 预留、未知消费和取消规则沿用原实现。

compaction_started 增加 compaction_version=task_aware_v1 和 current_task。SessionLog 核对所属轮次、实际输入、工具参数及输出；伪造问题、跨轮关联、工具证据或未知版本拒绝落盘。当前工具链和持久化消息共用同一工具来源校验函数。

只有模型请求成功、用量结算和完整摘要提交均成功，才激活新摘要；超时、无效文本、未知用量及保存失败仍保留原始历史和上一摘要。已知消费照常入账，未知消费不猜零。重启读取来源快照，不重跑摘要或工具。

录制起点保存 compaction_version；缺少字段的旧录制沿用旧摘要提示和输入，未知版本拒绝重放。新录制在离线运行中重建相同摘要及后续请求，不访问网络或重新执行工具。

## 验证

[9 项业务场景](../tests/features/test_task_compaction.py) 验证工具循环中触发摘要、实际问题与工具证据、成功/失败重启、原历史与覆盖范围、不可变输入副本、超大当前任务、手动无问题、旧新离线重放，以及伪造来源拒绝。连同既有摘要失败、保存故障、上下文、存储和重放回归共 173 项通过；全部使用模拟 HTTP，实际文件和 JSONL。
