# T6 只读工具并发

更新日期：2026-10-30

目标：同一次模型响应中的独立读取最多同时执行两项，减少等待；结果仍关联原调用 ID。
需求与阶段状态以 [能力扩展任务](agent-maturity-tasks.md) 为准。

## 当前交付

T6.1 调度器、T6.2 主/子工具循环接入及 T6.3 组合工程验收均已完成。
同批 file_info、list_directory、read_file、find_files、search_text、git_status、git_diff、git_log 最多两项并发。
命令、编辑、文档检索、Skill、MCP、计划、记忆、反馈和委派保持串行。无需改用户配置或模型调用协议。

## 调度契约

- ToolTask 固定调用 ID、准备函数、ToolCapability 和 parallel_safe 声明。
- 只有 READ_ONLY 且注册方明确声明 parallel_safe 的动作进入工作线程；只读并不自动代表线程安全。
- 未声明、未知能力、修改、命令、内部状态及委派均在调用线程串行执行。
  串行动作是屏障：之前的读取全部退出、结果交付后才执行，之后的读取也不能提前开始。
- prepare 按输入顺序在协调线程调用，返回可执行动作；on_result 同样在协调线程按原序调用。
  调度器不导入模型、存储、CLI 或具体文件/Git 实现。
- 工作线程只产生动作返回值或异常，不执行准备、结果回调、UI 或会话写入。
- 并发默认 2，可在组件构造时降为 1，拒绝更大数值；尚未新增用户配置。
  上限属于每个工具执行器；两个子 Agent 可以各自运行两个读取，仍沿用子任务数量与主会话共享额度。
  某项先完成就释放槽位，后续读取可以开始，不必等待排在它前面的慢任务。
- ToolResult 保存调用 ID 和原始返回值，完成先后不影响交付顺序。
  已知工具业务错误应由工具适配器转换为结果，因此单个文件缺失不终止其他查询。

## 取消与失败

父取消令牌或 KeyboardInterrupt 停止派发，并向当前并发组发送独立停止信号。
动作须定期检查这个令牌，阻塞操作须有有限等待；组内异常不反向取消父令牌或其他会话。
预检、程序异常、结果回调及线程创建失败都执行同样的清理，再传播原异常。
同一调度器拒绝重入；同批重复 ID 在任何准备动作之前报错。

独立调度组件默认最多等待整组 2 秒，组件允许设置大于 0 且不超过 60 秒的期限。
实际 ToolExecutor 使用 7 秒，覆盖 Git 进程树清理最多 5 秒及直接进程回收余量。
Python 线程不能被安全强杀：超时仍未退出时，公共 ToolCleanupError 在 call_ids 保留残留调用 ID，
以 tool_cleanup_error 记录轮次失败；原异常保留在异常链中，此调度器永久拒绝继续派发。工作线程为 daemon，残留不阻止解释器退出；
这不表示它已停止。不能使用“Future 已取消”或“join 已超时”冒充实际回收。

T6.2 的注册表以 parallel_handlers 明确声明可取消读取，READ_ONLY 本身不授予并发资格。
文件扫描逐项检查取消，文本分块有界读取；Git 使用可中断等待，退出后关闭输出文件。
规则、模式、参数和前置 Hook 按调用顺序预检；JSONL、后置 Hook 及结果编码都在协调线程执行。
对故意不合作的测试动作，验证清理失败和禁止续派，并由测试最终释放、回收线程。

子任务/CLI 在真实读取完成后暂缓返回，等待生产调度器的组取消令牌，不替换取消或清理实现。
CLI 使用与键盘 Ctrl+C 相同的 Python SIGINT 处理路径，未模拟操作系统无法中断的磁盘驱动阻塞。
