# B10 分块语境前缀

B10.1 提供独立的 ContextPrefixStore API，将短语境说明与原文分开保存。B10.2 已接入默认关闭的关键词/向量增强；原文和说明仍分别输出，不自动调用聊天模型。

## 为什么需要独立说明

原文某段只有“它在关闭后不自动恢复”，单独检索可能不知道“它”指什么。语境说明可以补充文档标题或邻近段落，让索引有机会找到该段；但说明可能不完整或理解错误，不能冒充用户能在文件里找到的逐字引用。

当前默认是本地确定性 ExtractiveContextBuilder，仅将文件名、章节标题和一个相邻片段的原文标为语境。它不调用模型、不解析缩写，也不声称正确解释代词。ContextBuilder 是可替换的窄生成接口，接收已经授权的有界材料，返回一段文字，没有文件或工具调用接口。

## 数据和限制

ContextPrefixStore.prepare 接收 DocumentIndex 成功刷新得到的 Corpus，返回每个分块的 ContextPrefix。调用者负责已有的读取授权。说明单独保存于调用者指定的 JSON 快照，源文件和原索引字节不变。

| 字段 | 含义 |
| --- | --- |
| chunk_id / path / source_version | 原始分块身份、来源及文件字节版本 |
| input_sha256 | 绑定目标原文前缀、邻块前缀、位置及输出上限的生成输入哈希 |
| generator | 稳定生成器身份；规则或模型改变须更新身份 |
| text / prefix_sha256 | 短说明及校验和，属于索引资料，不是引用原文 |
| basis | 实际提供给生成器的相邻分块 ID，最多两个 |

默认说明上限 300 字符，允许 1～1000；默认输入正文总上限 1200 字符，允许 32～8000。目标先分配最多一半正文额度，剩余分配给同一文件、同一版本的前后邻块。原文只截取前缀，同时保留 original_chars；行号表示整个分块，不能误解为生成器看过全部行文。最多处理 10,000 个分块，不按哈希重排同一长行拆出的片段。

缓存文件持锁生成。只有全部说明成功、格式正确且未取消，才原子保存并返回；非法、过长或空说明不自动重问。保存失败时旧完整缓存保留，不能将本次部分新说明当成成功。缓存损坏明确报错并保留文件，不通过静默重建掩盖错误。

当前来源、生成输入或生成器改变时重新生成；删除来源后旧说明从本次返回及成功保存的缓存移除。仅缓存输入、生成器和原文身份都匹配才能复用。说明与原文分离，后续检索接入也必须返回实际原文与来源，不把说明拼进引用正文。

## 验收与后续

[11 项场景](../tests/features/test_context_prefixes.py) 使用真实 DocumentIndex、文件锁和原子快照，覆盖说明与源文件分离、重启复用、同文件邻块及截断、源/生成器/窗口变更、删除和空库、生成失败/过长/空值/取消/保存故障、错绑来源与损坏缓存。故障仅注入生成器或原子替换边界，不替代源读取和持久化流程。

本阶段验证说明的身份和存储契约，没有证明检索改善。B10.2 的接入见下节；B10.3 已完成这些工程验收并提供显式真实生成入口，见下节；真实 LLM 生成质量仍待运行与人工判读。当前架构见 [系统架构](architecture.md)。

## B10.2 检索接入

```toml
[documents]
roots = ["docs"]
contextualize = true
context_prefix_chars = 300
context_input_chars = 1200
```

默认关闭；关闭时既不生成也不读取语境缓存。启用后，DocumentSearch 先成功刷新真实源文档，再准备短说明；源、说明缓存或保存故障都停止该次查询，不假装退回普通搜索成功。说明保存在与原索引对应的 .contexts.json，源版本改变使说明失效重建，删除后的旧说明不参与搜索。

关键词和向量使用“说明 + 原标题 + 原文”评分；返回的 Chunk、版本与行号保持原样，精排仍只读原标题及原文。向量缓存键同时绑定原分块与实际前缀，切换生成器或改写说明后不会误用另一份文本的向量。内容相同的前缀可以复用向量，不因为换了说明身份就捏造不同原文。

工具响应把说明放在独立 context_prefix 字段，并附“不是原文、可能错误”的提示；正文 text 不拼入说明。contextualization 记录实际生成器、窗口、说明数量和整套说明版本。说明及来源同样计入输出上限，放不下时整条省略；状态元数据都放不下则明确报错。源版本错绑会拒绝输出。

```powershell
python -m adam.document_search --workspace . --root docs --contextual search "某个项目代号"
```

可用 --context-prefix-chars、--context-input-chars 调整窗口。对 evaluate 使用 --contextual 时，本次选择的所有检索路线都启用同一确定性语境策略，逐题保存实际说明；它本身不是开关两种策略的效果结论。录制保存真实工具响应，离线重放不会重新生成说明或读取今日资料。

[13 项接入场景](../tests/features/test_contextual_retrieval.py) 覆盖关键词/向量/混合的邻块召回与原文分离、前缀变更后的真实缓存更新、来源修改删除和重开、关闭零生成、损坏明确失败、整体输出预算、工具日志/录制重放，以及配置和独立 CLI。向量评分用受控编码器，不能据此证明语义质量；相关既有文档与架构 126 项也通过。

## B10.3 指代、缩写与错误说明对照

[独立实验入口](../scripts/context_eval.py) 在全新目录创建四份合成资料、九个分块和六道固定题：ORION/NOVA 的相反重启规则、RPO/RTO 的不同含义与数值、一题字面控制和一题无答案。答案对应文件版本及真实原文位置，两路固定 k=1；不读取真实用户文档或旧会话。

默认纯本地，不加载聊天连接：

```powershell
python -m scripts.context_eval .cache/b10-local-01
```

真实生成必须同时显式提供开关和 LLM 配置，下面的命令会向配置的服务商发送合成片段，可能产生费用；本阶段没有自动执行：

```powershell
python -m scripts.context_eval .cache/b10-model-01 --model-generated --llm-config "$env:USERPROFILE/.adam/llm.toml" --max-known-tokens 50000
```

[ModelContextBuilder](../scripts/context_generation.py) 复用生产 LLMClient 的 JSON/SSE 接口，每个缺失说明请求一次，不传工具、不执行响应中的工具调用。最多 16 次请求，每次最多 512 输出 token，仍受总已知 token 与输入估算预留限制。实际服务端用量可能超过估算，超额记录后停止；用量未知保持未知并停止，格式错误不会反复重问。

先保存请求意图，再发送；记录中包含有界原文、模型名、请求内容、实际用量和受限响应预览，不保存连接密钥、HTTP 头或远端异常正文。硬中断留下 intent 时只能判断请求可能已发出，不能当成未消费。运行中能明确知道尚未发送或连接未建立时才标 not_sent。任何失败、取消、预算停止或证据保存失败后不发后续请求，不保存部分说明为可用缓存。

目录必须不存在；manifest 与 baseline 先落盘，完整成功后才有 report.json。失败尽可能留下 failed.json 与请求记录，不自动恢复、重发或覆盖旧目录。报告区分 extractive、mock_model 与 live_model；同一评估内语境版本变化也会停止，不能把两份说明的结果混在一份成绩中。

### 已运行的本地结果

[2026-11-01 完整证据](evaluations/b10-context-extractive.json) 运行的是确定性邻段摘录，模型生成请求为 0：

| 指标 | 原文检索 | 摘录语境增强 |
| --- | --- | --- |
| 五道有答案题 Hit@1 | 2/5 | 1/5 |
| MRR@1 / Recall@1 | 0.40 | 0.20 |
| 无答案返回空 | 1/1 | 1/1 |

两路均漏掉 ORION 否定规则及两个缩写数值；增强后 NOVA 的目标片段也没有排到第一。邻段说明增加了可匹配词，同时使相邻候选更相似，排序可能退步。结果没有为凑成绩删题或调规则；默认继续关闭该功能。此结果说明需要检验具体生成与索引策略，不能据此推断 LLM 生成一定改善或同样退步。

错误语境验收故意写入“无限重试”的说明：它确实能影响召回，但返回正文仍是实际的“最多两次”，并保留说明可能错误的标记。这验证了来源边界，不保证真实模型会忽略错误说明。模型生成后仍须人工核对：对象有没有串名、否定是否保留、RPO/RTO 是否混淆、时间单位是否改写、结论有没有超出输入证据。

[19 项场景](../tests/features/test_context_prefix_evaluation.py) 验证本地对照、实际 JSON/SSE 请求、密钥不入记录、非法/超长/未知用量/API/连接/超额/取消/误返回工具、发送前后保存失败、次数上限、错说明与原文隔离、说明版本变化、显式 CLI 开关和已归档退步。模型回复均模拟；真实 LLM 的语义效果仍待显式运行和人工审查。提交前执行 Ruff、Pyright 和全量 pytest。
