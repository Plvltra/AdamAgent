# E1 跨会话记忆：需求与验收

更新日期：2026-10-29
状态：E1.1 独立存储已实现并验收；E1.2～E1.5 待完成。
任务归属：[练手 TODO 的 E1](agent-practice-todo.md)。本文件细化需求，完成状态仍以主 TODO 为准。

## 目标与现有基础

用户在会话 A 明确保存一条约定后，在同一适用范围的新会话 B 中，程序能选中并提供这条记忆；用户能查看、修改和删除它。

现有能力包括会话历史、JSONL 恢复、上下文选择和摘要。E1 增加独立的可复用事实记录，不迁移现有会话，不把全部历史自动转换成记忆。

## 已实现：E1.1 记录与可靠存储

- 独立 MemoryStore 保存 memories.json v1；每次持有跨进程文件锁后重读，临时文件 flush/fsync 后原子替换。构造时不访问磁盘。
- 追加版本保留来源、原始创建时间和明确删除记录；修改须提供当前版本号，冲突时拒绝覆盖。
- 项目身份取最近的 .git 文件或目录所在根；无 Git 时取规范化工作目录，工作副本与移动后的目录不自动共享身份。
- 单条正文最多 4000 字符，整个版本文件最多 16 MiB；超过上限拒绝写入。时间须有时区。
- 业务验收见 [存储测试](../tests/features/test_memory_storage.py)：真实双进程并发追加、重启与范围隔离、版本冲突、替换失败、损坏拒绝、过期与项目根识别。
- 本阶段仅提供独立组件，CLI、配置和模型上下文尚未接入。

## 已确认的七项决策

| 决策 | 本版采用 |
| --- | --- |
| Q1 保存入口 | 明确命令管理，采用 /memory 下的 add、list、update、delete 操作；用户输入的操作直接执行并报告结果，不经过模型决定是否保存。 |
| Q2 适用范围 | 默认项目记忆，允许用户显式选择全局；使用前先校验适用范围，再判断相关性。 |
| Q3 使用方式 | 每个新用户轮次开始时，由程序自动检索相关记忆并加入输入；通过 /context 查看，不逐次询问是否读取。 |
| Q4 冲突处理 | 用户明确修改或替换原条目，保留更新来源；不让模型自动判定任意自然语言矛盾或合并事实。 |
| Q5 过期处理 | 支持可选过期时间，默认不过期；过期条目停止注入，仍可查看和更新。 |
| Q6 子 Agent | 只读继承主 Agent 本轮已经选中的记忆；第一版不开放子 Agent 独立检索、添加、修改或删除记忆。 |
| Q7 故障行为 | 记忆读取失败时明确提示本轮未加载记忆，然后继续聊天；写入失败明确报告未保存，并保护原记录。 |

这些决策是 Adam 的练习方案，不以其他产品的默认行为作为实现要求。

## 功能要求

| 编号 | 功能 | 可观察的完成标准 |
| --- | --- | --- |
| F1 | 记忆记录 | 每条记录有 ID、内容、项目或全局范围、创建及更新时间、来源、可选过期时间。能说明谁明确保存或更新了它；没有来源会话时不伪造会话关联。 |
| F2 | 增删改查 | 明确命令能添加、查看、修改和删除；拒绝无效参数与不存在的目标，不调用模型，不声称失败的写入已成功。 |
| F3 | 独立持久化 | 程序重启后记忆仍可用；多终端并发写入不会静默覆盖彼此的修改，失败不损坏此前有效记录。 |
| F4 | 范围隔离 | 项目记忆只能在对应项目使用；全局范围由用户明确选择。工作目录之外的读取权限不自动扩大记忆的项目范围。 |
| F5 | 检索与注入 | 先范围过滤及有效性检查，再做简单关键词检索。仅加入相关条目，记忆受独立可配置的输入限额及既有总上下文预算约束。 |
| F6 | 生命周期 | 修改后后续选择使用新版本；删除或过期后不再从记忆库注入。明确替换原条目，不用自动语义合并掩盖冲突。 |
| F7 | 可观察性 | /context 能展示本次预览选中的记忆及来源；实际请求记录能追溯当轮使用的记忆版本和内容依据。后续修改不篡改历史使用记录。 |
| F8 | 子 Agent 接入 | 子任务得到主 Agent 已选内容的只读副本，来源可识别，不获得额外范围或写入能力。 |
| F9 | 故障降级 | 读取失败与没有匹配结果分别表达；读取失败不伪装成正常空库。保存失败不清空文件，不报告成功。 |

命令具体参数、存储布局、项目身份的计算规则及检索限额属于后续实现设计，需要在对应小任务中说明并验证，不将其冒充已经确认的产品决策。

## 必须保持的边界

- 只有用户明确保存或更新的内容进入记忆库；模型回答、失败轨迹和子 Agent 总结不会自动成为事实。
- 记忆提供背景与约定，不改变工具权限或审批规则，也不覆盖用户当前明确要求。
- 每轮选择的记忆应保持一致，后续工具循环与子任务使用该轮选中内容；下一轮重新检查修改、删除和过期状态。
- 删除记忆只保证后续不从记忆库注入该条目，不抹除已有会话消息或历史诊断记录，也不承诺模型从已有历史中忘记它。
- /context 仍是预览，不等于尚未提交的新问题实际会选中的记忆；实际请求另留选择依据。
- 记忆读取降级只针对可选记忆能力，不改变会话日志、请求记账或权限错误现有的停止策略。

## 分步任务与验收

| 小任务 | 交付内容 | 重点验收 |
| --- | --- | --- |
| E1.1 记录与可靠存储 | 数据契约、独立持久化、项目与全局范围、来源与版本、并发保护 | 重启保留、范围不串用、并发不丢更新、写入失败保留原数据 |
| E1.2 用户管理与生命周期 | /memory 增删改查、明确替换、可选过期时间、错误反馈 | 命令不调用模型；无效目标不修改数据；旧版本、删除及过期状态可区分 |
| E1.3 自动检索与上下文 | 每轮检索、关键词匹配、输入预算、/context 预览及实际使用记录 | A 保存后 B 的实际请求含相关记忆；无关或越范围条目不注入；预算与历史工具配对保持 |
| E1.4 子任务与故障边界 | 子 Agent 只读继承；读取失败提示后继续；写入失败可见 | 子任务不能改记忆；不会扩大范围；损坏或权限异常不伪装成空库或保存成功 |
| E1.5 业务整体验收 | 固定任务覆盖上述流程，对比全部注入与相关检索 | 更新、删除、过期、重启、多终端、子任务及故障均有证据；比较实际输入内容与估算用量 |

按上述顺序推进。每个小任务完成后补业务验收、同步文档、验证并单独提交；本轮确认需求不代表这些功能已完成。

## 测试责任

实现时在 tests/features 中按跨会话记忆这一业务能力组织测试，基础存储及检索边界按需要放到模块测试中。当前不创建空测试或用跳过测试代替待办。

1. 会话 A 明确保存约定，新建会话 B 后检查实际模型请求包含选中的记录及正确来源。
2. 项目切换不泄漏项目记忆；全局条目只有在相关时注入。
3. 修改后使用新版本；删除或过期后不再从记忆库注入；原会话记录保持。
4. 重启保留条目；多终端写入没有静默丢失；损坏或写入故障保留已有数据。
5. 选中内容不超记忆与总输入预算，原有系统约束、当前轮次和工具配对不被破坏。
6. 子 Agent 只读使用主轮次选中内容；读取失败时聊天继续且错误可见。
7. 在相同样例上比较全部注入与相关检索，记录选中内容、输入估算及差异。

测试使用临时目录、受控时间和假 HTTP，不访问真实个人记忆或付费 API。离线验证只证明选择、注入和持久化流程；真实模型效果需另行人工验证，不因此重新启用已跳过的 V2.3。
