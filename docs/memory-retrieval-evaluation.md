# B06.3 记忆召回与来源验收

本阶段提供 [固定题集与运行入口](../scripts/memory_eval.py)，验证 B06 的范围、主体、时间、版本和主子继承闭环。另已使用真实本地 embedding 完成一次十题对照；结果包括失败题，不能据此声称模型总能理解记忆。

## 固定任务与执行方式

运行器在新目录创建两个项目和一组全局合成记忆，不读取真实用户记忆。十题覆盖原词、换一种说法、显式主体、同名歧义、偏好变化、过期、未生效、跨项目、全局资料和两条互相矛盾的当前事实。每题分别走生产 MemoryService 的 keyword、semantic 策略，交替顺序，使用相同资料、最多 3 条和 6000 输入估算 token 的预算；语义阈值固定为 0.5。

```powershell
uv sync --extra documents
python -m adam.document_search --cache-dir .cache/b06-model --model BAAI/bge-small-zh-v1.5 prepare-model
$env:HF_HUB_OFFLINE = "1"
python -m scripts.memory_eval .cache/b06-evaluation-01 --model-cache .cache/b06-model
```

准备命令下载公开模型；评估本身只使用本地缓存，不加载聊天连接配置，不调用付费 API，不上传记忆。目标目录必须不存在，已有结果不能覆盖。没有本地模型时生产策略仍可降级关键词，报告明确计数，不能把这次运行当成真实语义效果。

manifest.json 在查询前保存题集、期望身份及完整来源；逐题 JSON 保存实际策略、所选原文与版本、主体、相似度、警告和耗时；report.json 汇总全部 20 次结果。证据保存失败立即停止，保留已落盘的记录，不生成完整汇总。记忆读取失败记为 unavailable，不把空结果计成正确拒答。

## 2026-11-01 的真实本地结果

[完整来源与逐题结果](memory-retrieval-evidence.json) 来自一次实际 CPU 推理，使用 BAAI/bge-small-zh-v1.5、FastEmbed 0.9.1 和 ONNX Runtime 1.31.1。模型快照和 ONNX 文件 SHA-256 随证据保存。推理时设置 HF_HUB_OFFLINE=1，未改题、未调阈值后挑选成绩。

| 指标 | 关键词 | 本地语义 |
| --- | --- | --- |
| 有答案题完整找回 | 4 / 6 | 5 / 6 |
| Recall@3（7 条期望依据） | 5 / 7，71.4% | 6 / 7，85.7% |
| 应为空的题正确返回空结果 | 2 / 4 | 3 / 4 |
| 选中过期、未生效、其他项目或歧义主体 | 0 | 0 |
| 降级 / 读取失败 | 0 / 0 | 0 / 0 |
| 十题选择耗时合计 | 77 ms | 999 ms |

保留的失败和额外命中：

- “我动了几行实现，怎样确认没把已有行为弄坏？”两种策略都漏掉“代码修改后必须运行单元测试”。真实向量相似度不能保证所有同义表达命中。
- 询问已改变的回复语言时，关键词漏掉新偏好，语义策略找到简体中文；旧英语偏好均未进入当前结果。
- 询问未来发布代号时，关键词误选了两条当前发布策略；语义返回空。未生效的未来代号本身没有泄露。
- 在 BETA 项目询问 ALPHA 的私有仓库时，两种策略都选中无关的 BETA 约定。跨项目隔离通过，但相关性判断失败，这两个结果不能混为一谈。
- 查询全局沟通语言时，关键词还选中一条无关 BETA 约定；完整找回指标允许额外结果，不代表精确率为 100%。

同名王伟的含糊问题两组均提示主体 ID 并返回空；显式 @wang-dev 选到对应开发同事。冲突题均保留滚动发布和蓝绿发布两条当前依据，没有自动决定哪一条是真相。

这只是固定十题、单次、小资料集的检索对照。耗时包含不同的首次模型加载和缓存状态，不是稳态性能基准；命中不代表最终回答正确。更大题集、自然语言复杂指代及回答质量仍需后续评估，本阶段没有宣称这些已通过。

自动化使用模拟 HTTP 和确定向量，不下载模型；真实效果证据单独保存。提交门禁执行全量 pytest、Ruff 与 Pyright。架构见 [系统架构](architecture.md)，主体和时间规则见 [B06.2](memory-identity.md)，下一项为 B07 记忆整理。
