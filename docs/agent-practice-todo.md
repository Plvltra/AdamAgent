#### V4.1a 修改计划与 diff

- [x] 根据路径、旧文本和新文本生成修改计划，包含原版本标识、候选内容及 diff；规划不修改文件。
- [x] 旧文本必须恰好匹配一处；未匹配、匹配多处或空匹配均明确失败。

#### V4.1b 确认与可靠写入

- [x] 展示实际路径及 diff，只执行用户批准的那份计划；拒绝时文件字节不变。
- [x] 规划和执行都检查写入范围；读取授权不自动等于写入授权。
- [x] 批准后、写入前再次核对原版本；外部编辑使计划失效，要求重新读取和确认。
- [x] 采用临时文件和替换方式，避免把目标文件写成半截；说明版本核对与替换不是跨程序事务。
- [x] 验收：批准、拒绝、越界、外部修改、替换失败以及中文/换行保真；预期失败保留源文件。

## 每次练习的完成模板

复制以下条目到自己的阶段记录：

- [ ] 我能用一句话说明这次增加了什么用户能力。
- [ ] 我先设计数据结构、模块边界与失败行为，再写实现。
- [ ] 我能画出输入、状态变化、外部调用和输出的数据流。
- [ ] 我亲手写一个正常行为测试和一个有价值的故障测试，并解释 fixture/参数化/模拟的用途。
- [ ] 我用项目虚拟环境运行 Ruff、Pyright、pytest，不跳过失败检查。
- [ ] 我展示一次完整用户操作，记录未解决限制。
- [ ] 涉及真实模型效果时，我记录模型、提示版本、任务、用量与结果，不用单次演示证明稳定性。
- [ ] 我能解释 AI 生成的核心代码；不清楚的地方列为下一次学习任务。

测试环境约定：本人终端与 Codex 沙箱使用各自可写的临时和缓存目录，避免再次出现账户 ACL 冲突。不能用“沙箱里通过”代替本人终端可运行。
