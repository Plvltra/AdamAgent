## 进阶选做：一次只挑一项

### E1 跨会话记忆（6～10 小时）

书中关联：3.1.2 记忆层次、3.1.3 存储格式、3.1.7。前置：V1、V3。

- [ ] 区分聊天历史与可复用事实，先提供显式记忆添加、查看、修改和删除。
- [ ] 保存记忆内容、来源、时间和适用项目，先关键词检索；存储方案到该选做阶段再确定，不迁移现有 JSONL 会话。
- [ ] 仅注入相关记忆；处理相互冲突和过期的事实。
- [ ] 对比“每次塞入全部记忆”和“只检索相关记忆”的效果与用量。

验收：新会话能取回用户明确保存的项目约定，删除后不再从记忆库注入；不得把模型猜测自动认定为事实。

### E2 本地文档 RAG（10～16 小时）

书中关联：3.2.1 文档分块、3.2.3 稀疏检索、3.3.2 文件系统组织、3.3.4 智能体化 RAG。前置：V2、V3 和固定评估集。

- [ ] 选一个小文档集，先建立关键词搜索基线。
- [ ] 实现文档分块、来源路径、位置标记、文件更新后的索引刷新。
- [ ] 再选用一种 embedding 检索方式，比较召回效果；初版无需独立向量数据库服务。
- [ ] 回答中给出可核查来源；找不到证据时说明不足。
- [ ] 构造有答案、无答案、同词不同义、文档过期四类问题。

验收：比较检索结果是否包含答案，以及最终回答是否忠于证据，不能只评价语言是否流畅。

### E3 显式任务计划（6～10 小时）

书中关联：2.6.2 Agent 状态栏的构成（TODO、目标、约束和进展），另见1.2.4、5.1.3。书中没有单独的“规划章”；以下任务状态设计是工程化练习建议。前置：V4。

- [ ] 任务开始时生成简短可执行步骤，保存待做、进行中、完成、失败状态。
- [ ] 每步完成必须有关联工具结果，模型说“完成”不直接代表任务完成。
- [ ] 工具失败后允许修改计划，并限制重新规划次数。
- [ ] 对同一组任务比较直接工具循环与显式计划，观察计划是否增加有效性或只是额外开销。

验收：一个涉及两个文件的小任务，能看到计划与真实动作的对应关系。

### E4 基于反馈的反思与经验复用（6～10 小时）

书中关联：9.1 运行轨迹的学习信号、9.2.2 将经验写成指令、9.3。前置：V4、固定评估集。

- [ ] 以真实测试输出或用户纠正作为反馈，生成短的失败原因和下一步修正建议。
- [ ] 将经验与来源任务关联，人工确认后再保存为可复用条目。
- [ ] 限制反思轮数，不能反复自评直到口头宣称成功。
- [ ] 用不同的新任务验证经验是否有效，保留“不反思”的对照。

验收：改进能在结果上观察到，而不只是多了一段分析文字。这里没有训练模型权重。

### E5 双角色协作（10～16 小时）

书中关联：第10章，尤其10.2。前置：V5、明确的成本统计。

- [ ] 从一个执行者、一个只读审查者开始，先串行。
- [ ] 定义传递的任务、证据与结论，避免无上限复制全部对话。
- [ ] 限制往返次数和总预算，执行者统一负责写入，避免两个角色同时改文件。
- [ ] 审查者获得独立检查任务或不同证据，而非仅重复执行者的总结。
- [ ] 与单 Agent 在同一任务集上比较成功率、延迟和费用，收益不足时保留单 Agent。

验收：记录一次审查发现真实缺陷，也记录一次无收益案例；多角色数量本身不是进步指标。

### E6 Skills 渐进加载（4～8 小时）

书中关联：2.5.1、2.5.2、2.5.4。前置：V3、V4。

- [ ] 写两个本地任务说明，例如“运行项目检查”“定位测试失败”，明确适用条件与步骤。
- [ ] 初始上下文只加入名称和简短用途，确定需要时再读取全文及相关材料。
- [ ] 用匹配和不匹配任务验证触发行为，比较全部加载与按需加载的上下文大小。
- [ ] 明确 Skill 是任务指导，工具提供执行能力；Skill 不能绕过程序中的确认和权限规则。

验收：一个任务仅加载相关说明，仍能正确执行并报告结果。

### E7 接入一个 MCP 工具服务（6～10 小时）

书中关联：4.3。前置：V2、V5。

- [ ] 理解客户端与服务端，以及 tools、resources、prompts 的区别。
- [ ] 使用协议客户端接入一个本地只读服务，将工具映射到既有执行接口，不重写 Agent 循环。
- [ ] 测试服务未启动、断开、超时、工具错误与名称冲突。
- [ ] 比较直接调用函数和通过协议调用的成本与扩展收益。

验收：同一个查询任务可以分别通过本地工具和 MCP 工具完成；不要求自己实现完整协议。

### E8 界面、并发与交付扩展（独立规划）

- [ ] 多会话并发：同会话排队，不同会话隔离，取消 A 不影响 B。
- [ ] Web 界面：复用核心逻辑，实现会话列表、工具轨迹、确认和停止按钮。
- [ ] 部署：配置、数据备份、访问控制与重启恢复。
- [ ] 性能：先测热点，再决定是否把独立 CPU 密集模块改为 C++。

## 每次练习的完成模板

复制以下条目到自己的阶段记录：

- [ ] 我能用一句话说明这次增加了什么用户能力。
- [ ] 我先设计数据结构、模块边界与失败行为，再写实现。
- [ ] 我能画出输入、状态变化、外部调用和输出的数据流。
- [ ] 我亲手写一个正常行为测试和一个有价值的故障测试，并解释 fixture/参数化/模拟的用途。
- [ ] 我用项目虚拟环境运行 Ruff、Pyright、pytest，不跳过失败检查。
- [ ] 我展示一次完整用户操作，记录未解决限制。
- [ ] 涉及真实模型效果时，我记录模型、提示版本、任务、用量与结果，不用单次演示证明稳定性。
- [ ] 我能解释 AI 生成的核心代码；不清楚的地方列为下一次学习任务。

测试环境约定：本人终端与 Codex 沙箱使用各自可写的临时和缓存目录，避免再次出现账户 ACL 冲突。不能用“沙箱里通过”代替本人终端可运行。
