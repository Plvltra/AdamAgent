# E5 执行与独立审查对照

工程验收：`.venv/Scripts/python.exe -m pytest -q tests/features/test_review_records.py tests/features/test_independent_review.py tests/features/test_review_acceptance.py`。

模型选择由 MockTransport 固定，文件、编辑批准、子线程、JSONL 和 Python 检查实际执行。
这验证协议与协作边界，不证明真实模型能发现更多缺陷。

| 场景 | 单执行者基线 | 独立审查路径 |
| --- | --- | --- |
| 加法误写减法 | 交付前运行 add(2,3)==5 会失败 | 子 Agent 读取并指出第2行，主 Agent 批准修改，再次独立读取复审，真实 Python 断言通过 |
| 文件原本正确 | 直接完成，1次模拟请求、12 token | 1次审查，合计5次请求、60 token；文件不变，增加4次请求和48 token，无收益 |

测试分别记录实际耗时和协议报告 token；模拟 token 固定为每次12，不对应真实费用。
日志中的文件版本区分修正前与修正后。审查失败、引用不存在、文件变化、次数上限及重启有独立场景。
审查不执行 shell，主执行者的修改仍需原有批准；文件改动后的旧结论不再表示当前状态。

## 真实模型手动入口（待人工验收）

在临时工作目录准备两份相同任务，分别使用 `[review] enabled=false` 与 `true` 的配置启动 Adam。
每组使用新会话、相同模型、提示、额度和初始文件；至少重复三次，避免单次偶然性。
启用组明确要求“修改后 request_review，按意见修正，最多复审一次”；基线要求自行验证。

每次记录：任务最终断言是否通过、真实缺陷数/误报数、未完成项、主与子请求数、耗时、总 token。
费用根据当次服务商账单计算，不把估算 token 直接当金额。
另用完全正确的小文件检查无收益情况；审查增加成本而不改善结果时，保留单执行者路径。
用户自行运行会调用所配置模型；本轮自动验收未访问付费模型。
