# B06.2 记忆主体、事实时间与替代关系

本阶段给记忆增加显式身份和时间关系，继续使用原 MemoryStore、版本链和原子 JSON 文件。只处理用户明确保存的资料，不从姓名相似度推断身份，不自动合并冲突事实。

## 主体与消歧

主体由 key 和 name 组成：key 是稳定 ID（小写字母开头，最多 64 字符，后续允许小写字母、数字及 `._:-`）；name 是显示名。同名可以有不同 ID，显示名不会变成身份主键。未指定主体的旧记忆保持原格式，不推断它属于谁。

```text
/memory add --subject wang-dev --subject-name 王伟 -- 偏好先运行单元测试
/memory add --subject wang-art --subject-name 王伟 -- 偏好先检查视觉效果
/memory list
```

普通问题提到唯一显示名时，先选择该主体及未指定主体的通用资料，再进行相关性排序。显示名对应多个 ID 时，排除含糊条目并提示使用 `@主体ID`；例如 `@wang-dev 的检查偏好是什么？`。显式 ID 严格匹配，只选择指定主体，未知或大小写不符时不猜。比较两个主体可在问题中列出两个 ID。

没有主体指向的问题仍可检索带身份标签的资料；原文及主体一起进入模型，不能把其中一人的事实当成另一人的事实。范围始终先限制在当前项目和显式全局记忆，实体过滤发生在 embedding 前，不读取其他项目来消歧。没有建设自动人物关系图。

## 事实有效时间

valid_from 是可选生效起点，expires_at 是可选到期终点，均须带时区。当前有效条件为“未删除、已到生效时刻、尚未到期”；区间为左闭右开。起点不能晚于终点，尚未生效的记录在列表明确标出，不进入当前模型资料。

```text
/memory add --valid-from 2030-01-01T00:00:00+08:00 -- 新年度临时约定
/memory update ID --revision N --valid-from 2030-02-01T00:00:00+08:00 -- 推迟生效的约定
```

update 未给主体或 valid_from 时保留原值；`--expires` 沿用 E1 契约：未给表示取消到期时间。主体可显式更新，历史版本保留原身份；已有替代关系不能改成指向不同主体。当前召回按当前时间筛选，历史事实通过 `/memory list --history ID` 查阅，不自动解释自然语言里的任意历史时点。

## 原子替换旧偏好

```text
/memory add --supersedes OLD_ID --supersedes-revision 1 -- 新偏好
```

替代必须指向同范围下未删除的当前版本，且主体 ID 一致；未提供新主体时继承旧主体。跨项目、同名不同人、过时版本和悬空引用均拒绝，原文件不变。supersedes 保存确切旧 ID 和版本，后续查询能找到原依据。

新事实未指定 valid_from 时从保存时生效。程序在同一把锁、同一次原子文件替换中追加旧事实的到期版本和新事实：旧事实在新事实生效时结束；若旧事实已经更早到期，保留其结束时间。未来生效的替代在切换时刻之前仍使用旧事实。保存失败时两项都不生效，不存在只删旧偏好却没存新偏好的中间状态。

旧原文和版本永远保留。新事实删除或到期不会自动取消旧事实的结束时间，也不会把旧偏好恢复成当前事实；需要重新确认时显式更新或新增。更新旧到期条目仍须提供新 revision，并注意未给 expires 会取消到期，这属于用户的显式修改。

事实原文、主体、生效范围和替代来源随实际选择写入原请求日志。旧无元数据记录可读；新旧格式均经原契约校验。录制重放只使用当时快照，不重新读取今天的记忆或重新推断主体。
