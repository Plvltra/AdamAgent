## 已实现的目录边界

ToolRegistry 继续持有处理函数与执行策略，新增可选 groups 元数据和 directory() 入口。
分组由注册代码给出，不从工具名称、模型描述或参数推断；未声明时进入 extensions。
扩展不能重新标记已有工具；extended、guarded、with_mode 保留原分组、可信能力和执行规则。

| 分组 | 当前注册入口 |
| --- | --- |
| files | file_info、list_directory、read_file、find_files、search_text |
| git | git_status、git_diff、git_log |
| editing | replace_text、主任务 apply_proposal |
| code、commands | Python 结构查询；run_command |
| skills、mcp、documents、artifacts | 对应已启用且实际注册的扩展 |
| agents、planning、reflection、review、proposals | 对应主/子任务已有的协作或内部记录工具 |

分组名采用1～64位 ASCII 字母、数字、下划线或连字符，首位须为字母。
目录冻结原 Schema、可信能力和分组；后续扩展注册表或改写原说明不会改变已取得的快照。
简短条目只有名称、分组、摘要和能力；摘要合并空白、最多160字符，完整说明在被选择后原样提供。
非法名称、能力或无法编码的 JSON 在构造目录时失败。

模式过滤复用 check_tool_mode：
plan 中仅显示 READ_ONLY、SESSION_STATE、DELEGATE；未知能力、编辑和通用命令不进入可发现目录。
工具名称声称“只读”，或者分组被命名为 files，都不能改变可信能力判断。
路径权限依赖具体参数，仍在真实工具执行时检查；目录可见不表示任意路径可访问。

## 单轮选择与请求快照

| 对象或入口 | 已实现的契约 |
| --- | --- |
| ToolDirectory.listings(mode) | 返回模式允许的只读条目，不调用处理函数、模式提供者或路径检查 |
| ToolVisibility(directory, mode, loading) | 单轮选择器；on_demand 初始为空，full 初始包含当前模式允许的全部工具 |
| discover(names=..., groups=...) | 精确名称或整组选择；整批先校验再修改，重复项不重复添加，返回本次新增名称 |
| snapshot() / ToolExposure | 按原注册顺序冻结所选名称和完整 Schema；获取快照不表示请求已发送 |
| ToolExposure.require(name) | 名称未在此快照中则拒绝；通过后仍须原模式、路径、规则、Hook 和批准检查 |
| definitions() / schema_bytes | 返回独立 JSON 副本及完整 tools 数组的 UTF-8 字节数；字节数不是 token 数 |

某轮先生成快照 A，再发现 read_file，快照 A 仍不能调用 read_file；
只有后续取得的快照 B 包含其完整说明。T12.2 必须把实际发送的同一份快照与该请求返回的调用绑定，
不能在执行每个工具时重新读取已变化的选择集合，否则同批“发现后直接调用”会绕过约束。

新轮次和预览通过独立选择器取得初始状态；核心策略没有进程全局选择集合，也不读写会话。
T12.1 核心策略不控制聊天生命周期；T12.2 已通过实际 turn_id 与请求名单落实重置及来源绑定。

## T12.2 生产接入与配置

在用户主配置 config.toml 中设置：

~~~toml
[tool_discovery]
mode = "on_demand" # 默认；full 为全量对照
~~~

主任务与每个子任务在组装时分别创建 ToolDiscovery。每轮实际构造请求时按 turn_id
选择或重置；/context 等预览使用独立初始选择，不改变进行中的选择。
全量模式同样按可信能力过滤，plan 不提供编辑/命令；执行时仍保留 mode_blocked 原拒绝分类。

| 模型入口 | 参数与结果 |
| --- | --- |
| list_tools | group/query 过滤，offset/limit 分页；只返回名称、分组和简短用途，不激活工具。limit 默认20、最多100，完整条目页同时受 max_result_chars 限制 |
| discover_tools | names/groups 精确选择，整批校验、重复不累加；只返回选择数量，下次请求才附完整 Schema |

初始发现说明包含分组、数量和每组最多3个名称；其他用途通过分页目录查询，
不会默认重复发送所有完整说明。目录查询不执行底层动作，不扩张读取范围。
超过一项输出上限时缩小页；一项也放不下则明确失败，不能截断掉下一页位置。

Conversation 在发起请求前固定实际 tools 名单，整个返回批次使用同一名单。
例如本次同时返回 discover_tools(read_file) 和 read_file，后者被拒绝；
下一次模型请求提供了 read_file 后才可调用。仍须通过原模式、路径、规则、Hook、审批，
发现不是授权。普通知识回答可以直接结束，不要求先发现工具。

发现本身计入原请求、工具和 token 额度；扩展的 Schema 计入原输入估算，
放不下时照常停止，不自动放宽预算。请求开始记录的 context.tool_schema 保存
names 和 utf8_bytes：后者是 ensure_ascii=False、默认分隔符编码整个 tools 数组的大小，
不是 HTTP 线长或精确 token；整段输入仍使用 estimated_input_tokens。
旧日志缺少该字段时保持未知。录制保存实际目录和请求名单，重放不重新发现或执行外部工具；
当前新增录制已验收，未承诺旧版录制跨实现版本完全匹配。

12项生产业务与13项配置/分页/日志边界通过；同时回归原模式、录制、流式、子任务、记忆及文档功能。
旧业务脚本显式使用 full 保留其请求数与原断言，默认按需流程由新增场景负责。
真实模型是否正确选择工具及净 token 收益尚未付费验收；T12.3 的可复现同任务与组合对照见下节。

首次全量检查为1468通过、10失败：三处固定脚本夹具未显式使用 full，另有提案夹具仍要求 plan 提供编辑说明。补齐夹具配置并按新的过滤目录修正断言后，相关54项回归全部通过；生产权限、预算及执行规则未放宽。

## T12.3 整体业务验收与对照

[7项场景](../tests/features/test_tool_discovery_acceptance.py) 使用模拟模型 HTTP，
真实本地文件、JSONL、MCP stdio 服务、Hook 子进程和子 Agent 线程：

- 相同 note.txt 读取任务，两种模式均返回实际内容 value=42；同时统计额外模型请求和累计说明体积。
- 同一应用发现 Skill 与 MCP：查询目录不调用服务，按组发现后正文可加载；
  嵌套参数错误仍被原 Schema 校验拒绝，只有合法调用到达真实服务，关闭应用后进程退出。
- /new、resume 和关闭后重开应用均不继承上轮工具选择；重开会话不自动请求或重跑。
  此场景验证应用/存储重开，不冒充独立进程强杀测试。
- 发现整组工具导致输入超限时，沿原预算停止于下一次 HTTP 之前；不自动提升额度。
- 已发现 read_file 仍不能读取工作目录外的未授权文件，原 Hook 也能拒绝其真实调用。
- 主任务已经选择的工具不传给子任务；子任务分别发现、读取，命令仍返回 approval_required，
  不申请交互批准、不运行命令。主4次/子3次模拟请求的84个已知 token 纳入同一累计统计。

2026-10-31 本地同任务样本（15个全量工具，工具目录及临时路径变化可影响数值）：

| 指标 | full | on_demand |
| --- | ---: | ---: |
| 模型请求次数 | 2 | 3 |
| 初始完整工具数 | 15 | 2 |
| 初始 tools JSON 字节数 | 9,803 | 2,043 |
| 各次 tools JSON 字节数合计 | 19,606 | 7,295 |
| 各次输入 token 估算合计 | 6,721 | 3,332 |

该样本减少约63%的累计 Schema 字节，同时多一次发现请求。
估算来自程序现有上下文算法；不是服务端实际 token、缓存计费、耗时或质量结论。
模型选择采用固定脚本，不能据此认定所有任务都更省钱、更快或选工具更准确。
真实模型对照需用户显式运行，当前没有调用付费 API。

复现：.venv/Scripts/python.exe -m pytest -q -s tests/features/test_tool_discovery_acceptance.py。
输出 T12_COMPARISON 包含当前环境实测值；7项专项通过，完整检查作为本项独立提交门禁。
