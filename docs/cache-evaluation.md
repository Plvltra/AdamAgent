# B03.3 缓存与调用耗时对照

这是显式运行的练习脚本。工程流程已用模拟 HTTP 验收；真实模型缓存命中、延时和费用收益仍待个人显式运行，不因离线测试通过而视为已验证。

## 运行

在项目根目录使用当前虚拟环境。输出目录必须不存在；脚本使用固定合成文本，不读取用户项目、不执行模型工具，不默认读取模型配置。

~~~powershell
.\.venv\Scripts\python.exe -m scripts.cache_eval run "$env:TEMP\adam-cache-eval-01" --llm-config "$env:USERPROFILE\.adam\llm.toml" --allow-paid-api
~~~

只有显式 run、模型配置和 --allow-paid-api 同时提供才调用 API。默认每组 3 次，共最多 6 次；--rounds 允许每组 2～5 次。每次输出上限固定 128 token，本实验只要求简短确认。若回答因输出上限未完整结束，记录失败及已知消费并停止，不能据此认定缓存失效。

可选 --prices 接受三项十进制单价，依次为输入缓存命中、输入缓存未命中、输出的人民币/百万 token 价格。使用你实际服务商的当前价格；脚本没有内置价目表。未提供单价时费用保持 null。价格记录只是计算依据，不是最终账单。

查看已生成的报告不会加载配置、请求模型或修改文件：

~~~powershell
.\.venv\Scripts\python.exe -m scripts.cache_eval report "$env:TEMP\adam-cache-eval-01"
~~~

## 比较什么

两组调用复用同一份合成历史和当前问题，仅每轮运行状态文字变化：

| 组别 | 排列 |
| --- | --- |
| legacy | B03.2 之前的排列：动态提示拼入系统提示 |
| stable | stable_prefix_v1：稳定系统前缀，历史之后提供运行资料 |

请求串行交错，奇偶轮交换先后，每组第一轮标记 warmup。两个模型客户端各自记录逻辑前缀，HTTP 连接共享；前缀的上一请求指同组上一份输入，并非总顺序中紧邻的另一组请求。

首轮只在延时汇总中排除，实际消费和费用仍包含预热。服务端缓存不能由本脚本清空，跨组也可能共享；交错顺序与预热不能保证公平冷启动。两种布局还可能改变模型行为与输出长度，所以本报告提供观察数据，不证明收益只来自缓存。

## 数值口径

| 字段 | 含义 |
| --- | --- |
| estimated_input_tokens | 本地预算估算，不是服务端 tokenizer 或计费 |
| input_prefix | 逻辑输入的 UTF-8 字节、哈希、公共前缀；不是 HTTP 字节或实际命中 |
| usage | 服务端实际报告的输入/输出总 token |
| cache_usage | 服务端实际报告的 hit/miss token；缺省或矛盾保持未知 |
| elapsed_ms | 单调钟测得的一次 complete 调用耗时，含本地输入处理、网络、服务端等待及解析，不含证据文件写入 |
| cost_cny | 实际 hit、miss、output 与用户单价计算的费用；缺任一必要字段为 null |

费用计算为：(命中 token × 命中价 + 未命中 token × 未命中价 + 输出 token × 输出价) / 1000000。不用输入总量减命中数补造服务端未报告的 miss。

groups 分组展示状态数量、成功且非预热样本的平均/中位延时、hit/miss 的已知小计及未知请求数。cost_cny_including_warmup 只有该组已尝试请求的费用全部已知才提供。known_tokens 是可靠消费小计，usage_unknown 单列未结算或损坏记录；不能把小计当完整账单。

## 记录与故障

manifest.json 保存格式 cache_evaluation_v1、模型名、轮数、调用顺序、单价和 backend。01.json 等逐次记录开始及结果；文件在模型调用前创建并刷盘，之后保存可靠结果。API 密钥、认证头、连接地址和原异常文字不进入这些文件。

API/协议错误、取消、用量未知或记录失败都停止后续调用，不自动重试。已知失败消费仍保留；写入失败或进程退出留下 started/残缺记录时，报告保持未知，不重发和修复。原中断即使伴随失败记录写入错误仍继续传播。

50,000 token 是已知累计消费停止线；发送前也用输入估算与输出上限预留检查。估算无法保证服务端返回的单次实际消费不超过停止线；实际超出值仍如实报告，然后停止。未执行项目列为 not_run。

报告只读本地证据，损坏样本显示 invalid；文件不是防篡改凭据，不能从人工删除或伪造的记录证明真实消费。backend=mock 只验证工程流程，backend=live 才来自真实 HTTP 调用；即使 live，也仍需结合样本量、模型行为和缓存混杂因素判断效果。
