状态：T4.1 策略基础已实现；用户命令、模型上下文和子任务模式继承留在 T4.2，完整业务验收留在 T4.3。
当前普通启动保持原有 act 行为，尚未开放 /mode 命令。完整需求与进度见 [能力扩展任务](agent-maturity-tasks.md)。

## 用户目标与边界

plan 用于调查和形成方案，允许内部计划、反馈、会话记录及受限委派；不能执行文件修改或通用命令。
act 允许进入原有工具流程，路径规则、版本冲突、逐次批准及预算仍然生效。
模式由用户切换，不能从模型参数、工具文字、Skill 或 AGENTS.md 获得切换授权。
专用 Git 查询属于读取；run_command 即使参数看起来只读，也按进程执行能力限制。

## T4.1 实现

contracts/execution.py 定义 ExecutionMode、ToolCapability 和统一检查。
能力由可信注册代码声明，不发送为可由模型更改的工具参数：

| 能力 | 现有用途 | plan |
| --- | --- | --- |
| read_only | 文件/Git 查询、Skill 加载、文档检索、已配置且声明只读的 MCP | 允许，仍检查读取权限 |
| session_state | 计划和反馈记录 | 允许 |
| delegate | 受程序约束的委派和只读审查 | 允许，子任务继承限制由 T4.2 接入 |
| edit_file | 专用文件编辑 | 阻止 |
| run_process | 通用命令 | 阻止 |
| unknown | 未声明的扩展工具 | 阻止，不根据名称或描述猜测 |

读取指不修改用户目标资料；文档检索自身的受限索引缓存仍可更新。
MCP 声明来自用户配置的可信服务，不构成对任意外部服务的操作系统隔离。
注册时声明错误属于扩展代码错误，不能把模式检查称为沙箱。

ToolRegistry 支持注入只读模式提供者。执行顺序为：参数校验 → 模式检查 → 路径规则预检 → 工具及原有审批。
目录扩展、规则包装保留能力和模式；扩展不能重标已有工具能力，重复绑定模式会失败。
模式阻止返回 ok=false、status=mode_blocked，跳过专用执行结果编码器；工具轨迹保留，编辑和命令没有实际执行记录。
该状态不触发自动反思，也不能作为计划完成的成功证据。
