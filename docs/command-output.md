# B18 命令长输出的头尾与全文

## B18.1 源头捕获

[OutputCapture](../adam/tool_calls/command_output.py) 从已启动进程的 stdout/stderr 持续读取，分别保留固定前半和滚动后半。每条流保留的原字节不超过原 capture_bytes；读取批次为4096字节，解码和快照另有有界副本，不承诺进程总内存硬上限。输出未超过容量时逐字节保留；超过时保留开头、末尾，并在文字中标记中间省略的字节数。不会因停止读取而让满管道堵住进程。

[CommandTools](../adam/tool_calls/command_tools.py) 仍使用原批准、进程启动、期限及进程树清理；附件开启时容量仍由 artifacts.max_bytes 注入，否则沿用 max_result_chars 的原字节捕获额度。捕获与最终回传字符数是两种限制。B18.1 只验证源头；下述 B18.2 已将最终预览与附件完整性接入同一条回传链。

原结果及 command_finished 增加 output_capture，每条流包含：

| 字段 | 含义 |
| --- | --- |
| read_bytes | 管道已实际读取的字节数；eof=false 时不是命令最终总输出量 |
| omitted_bytes | 已读数据中未保留在头尾的字节数，包含被切开的 UTF-8 边缘残片；不包含标记文字 |
| eof | 是否确实读到管道结尾；读取失败或快照时仍在读取均为 false |
| invalid_utf8 | 保留段是否含需要替换的原非法编码；不检验已省略区域 |

UTF-8 在人为切口只省略不完整字符，避免把截断显示成乱码。原非法字节仍替换并明确标记。读取状态、头尾和计数在同一锁下取不可变快照；之后读线程继续工作不会改写已返回的结果。truncated 在字节省略、未读完或非法编码时为 true；已排空的空输出则完整。这里的头尾是按每条流各自顺序保留，不推测 stdout 与 stderr 的跨流时间顺序。

[19项源头验收](../tests/features/test_command_output_capture.py) 覆盖只在末尾报错的真实进程、准确字节数量、容量边界、中文/emoji切口、非法原编码、读取故障及仍打开管道的不可变快照。相关命令、附件和架构共73项通过（16.35秒），Ruff、528个文件格式和 Pyright 通过。读取故障和暂停使用明确的管道替身，真实进程保持原启动链。未调用模型 API。

原 _Output 的“持续排空”和“非法编码不完整”说明随实现迁到新模块；命令批准、先记开始事件和附件前不改原结果等说明保留。架构图已同步，主线按 AGENTS.md 三级验证规则执行。B18.2 见下文；B18.3 的取消与故障组合验收见下文。


## B18.2 最终预览与附件

[encode_head_tail](../adam/tool_calls/result_preview.py) 按实际 JSON 编码后的字符数缩短文字，命令事实、ToolArtifacts 和重复失败反馈共用。缩短总是重新取原文本两端，不把上次插入的标记再次当原文截取。preview_omitted_chars 分别记录每条流在展示层省略的 Unicode 字符数；这与 output_capture 的原字节省略不同，不能将两者相加。JSON 使用无多余空格的合法编码，为证据和状态留空间。

命令的 stdout/stderr 分别保留头尾；普通长工具结果的 preview 也保留原 JSON 文本两端，但 preview 自身不冒充完整 JSON。极小预算优先保留退出码、状态、附件引用和停止反馈；文本可能全部省略，省略数量仍明确。预算大到足以显示文本时按两端分配，不承诺任意512字符配置能同时容纳完整错误、引用和重复失败提示。不能连必要元数据都装下时明确失败。

ToolArtifacts 在预览之前将取得的原结果交给原 ArtifactStore：单份、会话和数量配额仍在锁内核算；容量允许且上游完整时可以逐字读回全文。源头已经丢弃、非法编码或管道未读完，或保存配额不足，都保持 artifact.complete=false。source_truncated 表示工具取得的原结果是否已不完整，truncated 表示最终回传有省略。total_bytes 的既有含义是工具结果 JSON 文本字节总量，不挪用 stdout 的字节数；上游不完整时仍未知。保存失败只返回不可用提示，不自动重新执行。

发现并修复第三处尾部丢失：命令非零退出后 encode_progress 添加 no_progress，原实现把已经编码的整个结果再取前缀。现在 ToolInvocation 显式提供宿主原结果用于文本预览，状态、附件引用及重复失败结论仍取已验证结果和宿主观察，附件正文不改写。JSONL 中 tool_finished 与实际模型输入一致。

[7项新增验收](../tests/features/test_command_output_preview.py) 通过模拟 HTTP 驱动真实命令，核对双流开头/末尾进入模型输入、非零退出、足额完整附件、超额不完整、附件故障不重跑、无附件512/1024/4096预算与中文/emoji/转义计数。相关命令、附件、重复失败和架构152项通过（37.76秒）；Ruff、531个文件格式与 Pyright 通过。旧重复失败测试改为检查实际保存的 output 长度，而不是重新序列化后添加空格的长度，原停止和引用断言保留。

另有附件存储、参数、主子隔离、录制重放和配置78项通过（21.33秒）。注释审查保留“先保存正文”“不改原结果”“反馈不能改变已发生动作”等说明，共同预算逻辑移到 result_preview；主线按 AGENTS.md 三级验证规则执行。模型仅是预设 HTTP 响应，不证明真实模型一定会根据末尾错误作出正确判断。


## B18.3 真实故障与恢复

取消时旧逻辑只写空的 interrupted 结果，会丢弃已经排空管道的证据。现在 CommandTools 在终止进程树并等待读取线程后取得头尾快照，通过仅本模块使用的内部异常传给公开入口，先保存 command_finished，再继续抛出原 KeyboardInterrupt/EOFError。CLI 无需了解新增异常。日志失败仍按原失败规则停止，不重新运行命令；若在启动或清理本身中断、没有可靠快照，则明确 truncated=true，不将空字符串视为完整输出。

用户取消仍结束当前轮次，不为保存全文再继续工具链。已有头尾、EOF、已读/省略字节和退出码留在命令事实中；没有已提交来源的附件不会凭空变成可读引用。超时仍返回 timed_out 供模型说明结果；随后回答提交成功只表示聊天轮完成，不能把失败命令改为执行成功。EOF 是管道结尾，不是任务成功证明。

[组合测试](../tests/features/test_command_output_acceptance.py) 新增3项：

- 独立宿主通过原应用启动真实命令及其子进程；两条管道输出中文/emoji长日志和尾部标记后，辅助线程投递 Python SIGINT。验证主任务中断、仅1次模拟请求、两个实际进程均退出、头尾持久保留且重启不重跑。
- 相同真实进程由原2秒命令期限停止，验证 timed_out、两条流尾部和子进程清理；下一次模拟请求说明失败后，聊天轮正常提交。测试从正式 execution_report 读取轮次状态，不错误要求成功也必须存在 turn_finished 事件。
- 超出捕获及附件配额的双流命令录制后离线重放，保留头尾与 complete=false；重放期间禁止网络和进程启动，原命令事实保持。

[独立宿主](../tests/features/support/command_output_worker.py) 和 [实际长输出任务](../tests/features/support/command_output_task.py) 都有明确用途，测试不向 pytest 主进程投递中断。SIGINT 走 Python 实际中断处理路径，不声称测试了物理键盘；超时和清理使用生产实现。只在最后报错、多字节、双流、配额及保存故障的前两阶段场景继续复用。

相关源头/预览/命令和架构71项通过（19.25秒），已有命令/批准取消、附件及重复失败26项通过（31.21秒）。Ruff、534个文件格式与 Pyright 通过，新增文件全文和生产差异已审查；原“终止进程树与回收”说明保留并补中断快照契约。主线按 AGENTS.md 三级验证规则执行。B18 工程验收完成，下一步 B19.2 命令隔离后端接入；没有调用付费模型。


## B19.2.3 隔离命令的差别

新隔离命令共用最终预览与附件，但 Linux 后端输出达到64KiB就停止，保留的是实际取得片段，不能称为进程最终尾部。模型预览和重复失败反馈保留 environment、reason 与 exit_code；极小额度的反馈可只返回状态、完整失败指纹、附件读取凭据/完整性和 preview_omitted_chars，正文全部省略。此时可省略附件的 saved_chars/format 展示字段及重复 policy，完整值仍在附件或命令事实日志。33项 [接入验收](../tests/features/test_isolated_command_flow.py) 包含512字符的非零退出、超时、输出停止和连续失败最终停止；原宿主命令捕获与预览场景继续回归。


B19.3.1：隔离后端明确输出 invalid_utf8；解码替换造成字节损失时标记 truncated，附件 complete=false。合法的替换字符本身不算损失。真实字节验收与日志/重放验证见 [隔离边界](runtime-isolation.md)。
