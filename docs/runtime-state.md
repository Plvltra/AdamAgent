# B04 模型可见状态

当前完成 B04.1 数据契约和 B04.2 请求接入。主、子 Agent 的普通工具循环在历史之后、当前完整工具链之前提供只读状态；正常终端不新增逐次用量输出。B04.3 的组合验收另行推进。

## 数据从哪里来

| 状态 | 口径与来源 |
| --- | --- |
| requests | RequestPolicy.snapshot：本轮物理尝试，明确未发出的连接重试也占次数；未开始的下一次仍在 remaining 内 |
| tools | 宿主统计的本轮全部工具次数，不能用只统计文件修改的 ToolBudget 替代 |
| tokens | SharedTokenBudget.snapshot：锁内同时读取整组已结算消费、未知标记和在途估算预留；不跨线程读取会话文件 |
| failures | NoProgressGuard 产生的连续相同失败计数与 SHA-256 指纹；未观察为 null，0 不意味着任务成功 |
| environment | 宿主已验证的绝对工作目录和 ExecutionMode；没有 API 密钥、环境变量或新授权字段 |
| pending_agents | 待收集子任务 ID；null 是未知，[] 是确认为无，出现 ID 不表示其任务成功 |

这些值通过 [RuntimeState](../adam/contracts/runtime.py) 汇总。它是不可变值对象，as_record 复制完整 JSON 数据，格式为 runtime_state_v1；内部日志解码严格验证字段、模式及派生余量，不把模型提供的字典转成可信状态。

## 剩余额度不等于执行许可

请求和工具 remaining = max(0, maximum − used)，实际 used 超额时仍完整保留。token remaining = max(0, maximum − known_used − reserved)，但仅在消费和预留均已知时计算；否则为 null。known_used 保留已知小计，不因其他消费未知而清零。

例如总额度 1000、已结算 150、两个在途请求分别预留 200 和 300，快照显示余量 350。读取快照本身不预留这 350，其他子任务可能立即占用它；真正请求时仍必须通过共享账本的原子 reserve。预留是本地估算，也不能保证最终服务端消费不超过上限。

整个 RuntimeState 汇总的各来源并非全局原子快照；只有共享 token 的消费和预留在同一锁内读取。注入文字标明输入构造时刻，连接重试会复用原输入和状态。下一次重新构造会纳入已经发生的重试、摘要、反思请求与工具调用；发送前的实际请求计数、共享预留和权限检查保持。

## 有界输入与真实记录

[RuntimeStateReader](../adam/application/runtime_state.py) 接受宿主的状态查询函数，Conversation 只传当前真实请求/工具计数，不读取具体工具执行器内部成员。主会话取整组账本、当前未交付子任务 ID；子会话沿用同一组额度，但失败检测与工具次数各自独立，不获得再次委派能力。

模型状态文字最多 4096 字符。工作目录最多显示 256 字符，超长明确标记；待收集列表最多显示 8 个、每个不超过 64 字符的完整 ID，同时保留总数和截断标记。计数与未知值不截断。完整来源对象保存在 request_started.context.runtime_state，实际文本可按同一格式重建；它不进入成功问答历史，也不代替工具或计划证据。

状态资料以 user 角色参考消息提供，由固定包装说明其不增加授权；不是 system 指令。状态文本计入 ContextBuilder 的 runtime_tokens 和受保护输入预算；记忆选择也先预留该输入。状态或日志读取失败会停止本轮，不猜零、不发请求；保存记录失败继续遵守原有存储边界。

/context 仍为无副作用的基础预览，不读取实际轮次的状态来源，明确提示尚未包含执行时状态快照。实际发送重新估算，因此预览余量不是请求一定能发出的承诺。专门摘要与反思保留各自协议，不插入普通工具循环的状态消息。

录制起点使用可选 runtime_state_version，状态来源观察保存于 context/state；回放比较真实循环的次数并读取当时冻结的外部状态，不查询当前线程或重新执行工具。旧排列以及旧稳定排列录制没有该字段时不增加状态查询；未知版本、错误模式或不一致的派生余量拒绝读取，不自动改写。

## 验收与下一步

7 项 [业务 API 场景](../tests/features/test_runtime_state.py) 验证真实重试计数、嵌套预留/释放、未知消费、旧快照无法越过执行检查、连续失败重置和不可变汇总。11 项 [数据边界](../tests/test_runtime_state.py) 拒绝负值、布尔假计数、错误模式、相对目录和重复子任务 ID；连同架构检查共 39 项通过。

B04.2 新增 5 项 [请求业务场景](../tests/features/test_runtime_context.py) 和 7 项数据边界：实际重试和文件失败后输入/日志一致、离线重放、旧录制、预览、状态读取失败、损坏记录及有界文本。连同上下文、协作、恢复、附件和模式等相关回归，共 208 项通过。既有子任务模拟服务按最近任务输入识别任务，预算场景使用真实首请求校准；原文件效果、并发、审查和强杀断言保留。

下一步 B04.3 进行主/子任务与失败、额度组合验收。CLI 仍按需查询用量，不恢复每次请求都打印 token，也不新增 /turn 或 /diagnose。
