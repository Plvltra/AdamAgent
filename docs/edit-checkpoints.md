# 修改检查点与撤销

范围：T7.1 已实现显式检查点存储与 JSONL 对账；编辑工具自动保存、/undo 和完整撤销验收分别属于尚未完成的 T7.2、T7.3。需求以 [能力扩展任务](agent-maturity-tasks.md) 为准。

## 已实现的存储契约

EditCheckpoint 固定会话、编辑、轮次、请求、工具调用、目标绝对路径、原始字节、修改前哈希及预期修改后哈希。原字节不经过文本重编码，保留 BOM、换行形式和最后一行。目标路径只是来源数据，读取检查点不读取或修改它。

CheckpointStore 使用如下位置：

~~~text
<会话根目录>/_checkpoints/<session_id>/<edit_id>.json
<会话根目录>/_checkpoints/.locks/<session_id>.lock
~~~

JSON version 为 1，original 使用 Base64，两个版本使用 SHA-256。会话 ID 为 8 位、编辑/轮次/请求 ID 为 32 位小写十六进制；工具 ID 最多 1024 个 UTF-8 字节，目标路径最多 32768 个 UTF-8 字节。存储格式不接受额外字段、重复字段、不支持的版本、坏编码或不匹配哈希。

调用方注入 max_bytes，沿用编辑文件字节上限；存储层不依赖配置模块。允许的参数范围与现有文件配置一致，为 1～100000000 字节。编码文件读取上限为 Base64 最大长度加 64 KiB 元数据；解码后再次检查原字节大小。下调文件上限后，超过新上限的旧快照也会明确拒绝读取。

## 可靠写入与失败边界

同一会话的快照读写共用 FileLock，覆盖不同存储实例；锁忙时报告失败。独立临时文件写完后 flush、fsync，再以同目录 os.replace 发布。相同 ID 和相同内容允许重复保存；不同内容拒绝覆盖。

发布前写入、同步或替换失败，不生成正式快照，不修改目标文件。仅清理本次临时文件；崩溃遗留的临时文件不会自动加载、自动发布或自动删除。缺失或损坏的正式快照明确报错，不用目录中其他文件替代。

会话/编辑 ID 在拼接路径前校验，存储根不得通过链接重定向，子路径解析后不得越界。路径检查与文件操作不是跨进程事务，也不构成操作系统沙箱。fsync 加原子替换用于正常进程故障恢复，不承诺所有文件系统在掉电时都已持久化目录项。

## 与成功事实对账

SessionStore 提供两个显式接口：

- save_edit_checkpoint：从已登记的 edit_planned 取来源及版本；只接受进行中轮次里尚未开始的编辑。原字节必须匹配计划版本。保存失败必须阻止调用方继续编辑。
- load_edit_checkpoint：取得会话锁，必要时按已有机制恢复日志；仅对 status=applied 的编辑返回快照，并比较来源、路径及前后版本。

快照只有预期结果，不能自行证明编辑成功。planned、not_started、unknown、denied、conflict、failed 均不能因快照存在而变成成功。即使文件已变为候选内容，缺失 edit_finished 仍保留 unknown。成功编辑缺少快照也不能用于撤销。

这两个接口目前需要显式调用；不会改变已有 replace_text 的行为，也没有新增终端命令。T7.2 将在用户批准后、edit_started 和文件副作用前接入保存，并实现逆向差异确认、外部版本冲突和撤销来源记录。T7.3 再验收实际进程中断、重复撤销和编辑→重启→撤销。
