## E5 推荐决策

现有主 Agent 是执行者，审查者是独立只读子 Agent，不额外创建执行者线程。
每主轮最多两次审查：首次审查后允许主 Agent 修正并复审。沿用 V6 的共享消费、独立日志和取消。
审查者必须自己读取指定文件，引用子轮真实 read_file ID、文件版本和行号。
findings / no_findings / incomplete 是模型判断，程序只验证结构和依据，不保证缺陷判断正确。
未完整读取不能给出 no_findings；文件变化导致旧结论失效。审查进行中主 Agent 不执行编辑或通用命令。
目标在读取后被外部删除时，原读取凭据保留，收集记录为 stale，不停留在 pending。
不自动审查每个简单问题；模型按任务或用户要求使用专门工具。达到上限、失败或中断明确保留未完成状态，不无限来回。

E5.1 已加入 review_requested/review_finished 和 reviewer 角色。子任务 completed 只表示回复提交；审查结论独立校验。
父轮中断/重启后未收集审查标 interrupted，不自动重发；子 JSONL 保留。
E5.2 已接入 request_review / collect_review；审查中暂停修改和新委派，必须收集后才能结束。
[review] enabled/max_rounds 控制启用与次数，仍服从子创建数和共享额度。

## E6 推荐决策

项目 skills/<id>/skill.toml 只放名称、用途和允许加载材料列表，SKILL.md 为正文。
名称与用途在加载目录时去除两端空白，后续上下文使用同一份规范化数据。
这是 Adam 的本地 TOML 格式，不声称兼容其他 Agent Skills 格式；不为此引入 YAML。
初始只读目录，load_skill 按需读正文或某份材料；引用版本和内容随工具记录保存，日志回放不重新读取文件。
正文沿用已有工具上下文预算，不能绕过权限和审批，也不能申请新执行能力。
两份示例为 verify-project 和 diagnose-failure，先发现项目实际检查入口，不硬编码 Adam 的检查命令。

## E7 推荐决策

使用官方 Python MCP SDK 和本地 stdio 服务，默认关闭，配置启用后才启动。
首次接入仅提供明确只读的查询工具；服务声明不是操作系统沙箱，必须选用可信的本地程序。
使用服务别名前缀隔离名字，保留完整参数 Schema 校验，工具错误回传，断开/超时不自动重发。
不重写 Agent 循环，不做远程服务、认证管理、通用插件热加载。
用真实服务子进程验收，比较冷启动和连接复用后的调用；MCP 的价值是协议解耦，不声称比函数调用更快。
