# 文件搜索与续读

## B21.1.1 已实现的基础

B21.1.1 建立独立扫描与游标 API；B21.1.2 已将 `find_files`、`search_text` 和 `list_directory` 接入，聊天可继续取得第51条命中。下面保留基础契约，实际接入见末节。

| 接口 | 契约 |
| --- | --- |
| [capture_inventory](../adam/tool_calls/query_scan.py) | 每次检查 PathPolicy，按相对路径稳定排序；数量限制包括被跳过的目录项，根对象单独保留 |
| QueryInventory | 保存授权普通文件/目录的元数据与跳过数量；不包含文件正文，摘要不等于跨文件原子快照 |
| [QueryCursor](../adam/contracts/file_query.py) | 绑定规范化查询摘要、扫描版本和结果偏移；严格有界格式，来源或查询变化须从头查询 |

递归时跳过缓存、`.git`、symlink 和 junction，不泄露被拒绝路径；显式列举目录可包含 `.git` 目录项，但仍不越过权限。取消、扫描超限、对象消失都失败，不把部分清单冒充完整结果。调用方提供取消和期限检查；本 API 不自行创建线程或期限。

游标未签名、不是访问令牌，不授予任何路径权限，也不代表存有可恢复的服务端快照。B21.1.2 文本查询已加入实际读取字节的版本，不能仅凭 mtime 判断内容没有变化。目录扫描不是事务，后续仍需复核扫描期间变化并明确观察局限。

## B21.1.2 实际工具与模型续读

[FileQueries](../adam/tool_calls/file_queries.py) 负责扫描、版本复核和页面收集，FileTools 保留原入口与单文件读取。普通和并发调用沿用原工厂，每次调用独立状态，不依赖上次工具对象还活着。无需增加数据库、后台索引或新终端命令。

| 行为 | 具体约定 |
| --- | --- |
| 翻页 | 原参数外增加cursor和limit；把next_cursor原样带回，同一路径/查询/匹配方式才能继续；页大小允许调整 |
| 页面大小 | 文本最多50条，文件/直接目录最多200条；按最终JSON长度保留完整条目，不让原编码器变成丢失游标的preview |
| 单条过长 | 明确失败并提示提高max_result_chars或缩小范围；不跳过当前条目，匹配行最多展示500字符并标line_truncated |
| 来源变化 | 每页重新授权，比较规范查询和扫描版本；文本纳入实际字节SHA-256；扫描结束再查目录元数据，发现变化即失败 |
| 不完整范围 | skipped_entries是被排除目录项数量，skipped_files是匹配glob但无法搜索的文件数量；不能把这类无命中说成整个目录无匹配 |
| 限制 | 原条目数、单文件大小与协作期限保留；新增tool_limits.max_scan_bytes默认32MiB，上限100000000字节，每页重新计量 |
| 旧调用 | list_directory仍接受offset并返回next_offset，但旧offset无版本保护；不能与cursor混用 |

总读取预算成功时按实际字节扣减；无法取得完整读取数量的错误保守扣除本次可读上限，可能提前停止，但不会超预算后继续成功。检测文件增长预留一个字节；明确超大文件不打开，只记跳过。超时与取消贯穿目录、文件和行处理，是协作停止，不宣称能强制中断所有文件系统调用。

扫描清单包含授权范围的元数据，因此即使不匹配glob的文件发生变化，也可能让旧游标失效。这是偏保守的版本策略。两次目录观察和文件摘要不是跨文件原子快照；游标不授予权限。精确字面搜索仍为默认，显式正则留在B21.2。

[14项新场景](../tests/features/test_file_query_pages.py) 验证三个工具各自61项续读不重不漏、512字符页面、单条过长、恢复mtime后的字节变化、撤权、跳过与总字节拒绝、扫描中变动和TOML。模拟HTTP驱动真实应用先取50条再取第51～61条，两次工具执行写入JSONL；更改源文件后禁止FileQueries、网络和进程，离线重放仍匹配。模型回复为预设，不代表真实模型自主选工具效果。

相关160项通过（50.91秒），包括原工具、取消、记忆保护、循环、附件和架构；Ruff、572个文件格式及Pyright通过。附件旧场景改用真实转义文本触发长结果，19项原场景数量与主要断言保留。主线按 AGENTS.md 三级验证规则执行。
