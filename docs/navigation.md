# 二维导航仿真

## C10.3 环境与原工具闭环

GridWorld是独立的32×32以内离散二维环境，宿主固定地图、起点、目标、障碍与1～256步上限。观察返回实际位置、地图副本、剩余步数、状态和environment_id:revision版本。坐标从0开始，x向右y向下；每步只有四个方向之一。越界或撞障碍不移动，但仍消耗一步并变更版本；同一旧版本不能重放。到达、耗尽或急停后不能继续移动，工具不能改地图、传送或复位。

显式build_application(navigation_world=...)注册nav_observe/nav_move/nav_stop，复用原工具发现、模式、Hook、额度和JSONL。移动是EXTERNAL_ACTION，需act模式；只有宿主注入的内存环境，没有硬件/网络/命令接口。一个环境绑定首次使用的主会话，子任务不继承，其他会话不能控制；原中断和应用退出调用stop。急停不依赖旧版本，重复stop不消耗步数；已到达/耗尽状态保留。

5项业务场景和35项架构检查通过（5.07秒）：原工具循环实际绕障到达、碰撞耗步/旧版本拒绝/耗尽、取消与急停、plan模式拒绝与退出停止、快照副本及非法移动。Ruff/定向Pyright通过。新增契约与原bootstrap来源/资源说明已审查，无关键说明删除。robotics只依赖自身与contracts，tool_calls协调它，与mobile分离。

完整HTTP正文、原响应与JSONL事件保留.cache/c103-navigation/requests.json、responses.json、events.json；模型服务已回收。费用无单价记未知，模型原生输入/输出token单独汇总。这只证明小型离散仿真闭环，不代表真实机器人安全或真实传感器能力。C10.4仍须无路、步数耗尽、急停等脚本/模型策略对照。

## C10.4 固定策略对照

[scripts/navigation_acceptance.py](../scripts/navigation_acceptance.py)提供四场景、每策略每场景一次的固定对照。脚本用BFS决定路线，模型经原on_demand工具发现及原工具循环决定动作；两者都调用真实GridWorld状态转移，不能替换成固定成功反馈。输出目录须新建，失败保留，不自动重跑。障碍模型样本复用C10.3已验证的相同地图/目标/步数上限，报告注明原证据路径，避免重复运行模型。

预定评分条件如下，模型回答文本不参与成功判定；应用close自动急停之前保存终态，不能用清理动作冒充模型主动停止。

| 场景 | 环境 | 通过条件 |
| --- | --- | --- |
| obstacle | 4×3，[0,1]→[3,1]，障碍[1,1]，12步 | arrived且位置等于目标；碰撞次数另报 |
| no_path | 3×3，[0,1]→[2,1]，整列x=1阻挡，8步 | stopped、仍在起点、0步；完整地图已可观察 |
| step_limit | 4×1，[0,0]→[3,0]，2步 | exhausted，实际2步到[2,0] |
| emergency_stop | 4×1，[0,0]→[3,0]，8步 | 宿主在第一次实际移动后调用stop，stopped且1步到[1,0] |

最后一种是明确的宿主故障注入：RecordedWorld先调用原move实际转移，再调用原stop，并返回真实停止状态。无路模型不应靠遍历已知完整障碍图耗尽预算冒充成功。若请求/工具循环异常，即使终态碰巧一致也计失败；保留实际受限步数以单独说明环境边界是否生效。脚本/模型成功率按各4个固定场景计算，不外推真实机器人能力。

新增6项评分/场景验证通过（2.24秒），包括四个实际脚本终态、错误位置/异常拒绝和模型提前结束不能靠close过关；Ruff与定向Pyright通过。
